它是什么

  • 规模：232 个特效，分 20 类（火、爆炸、水、冰、闪电、科幻、近战、受击、投射物、出生与死亡、奥术、神圣、暗影、状态、自然、天气、UI、拾取、转场、小动物）。本站数过源码文件，确是 232 个。
  • 形态：每个特效就是 src/fx/<类别>/<名字>.js 一个文件，只依赖仓库自带的 src/core，没有第三方依赖，也没有图片素材。
  • 两种用法：网页游戏（原生 canvas、Phaser、PixiJS、Kaplay、three.js）直接 import 代码；其他引擎（Godot、Unity、GameMaker、Defold、LÖVE、Bevy）用 node tools/render.mjs <id> --sheet 导出透明 PNG 图集 + Aseprite 格式的 JSON。
  • 可调：任何特效都能传 palette（从暗到亮的一串颜色）换色，还有 seed（换一个等价的随机版本）、flip（朝左）、angle（旋转）、light（光晕强度），以及各特效自己的参数。
  • 出处：方法来自 Hugo Duprez 两天前（2026-10-28）发表的博文；仓库的粒子模拟核心 src/core/sim.js 和相当一部分特效改编自他在 Sprite Fusion 开源的像素特效（同为 MIT），仓库在 README、NOTICE 和各文件开头都写明了。
  • 发布方：Patch（patch.gg），GitHub 组织账号。仓库 2026-10-30 14:43（UTC+8）创建；截至 2026-10-31 11:45（UTC+8）约 378 星、46 个 fork（GitHub 官方 API）。

重点：pixelfx Skill

README 里“the skill”一节只有几行，真正的内容在 skills/pixelfx/SKILL.md（124 行，见附录二）。它把“用这个库”和“扩充这个库”写成了 Agent 可以照做的步骤。

安装

作为 Claude Code 插件安装（仓库自带 .claude-plugin/marketplace.json 与 plugin.json）：

/plugin marketplace add patch-gg/pixelfx
/plugin install pixelfx@pixelfx

或者把 skills/pixelfx 整个目录复制到 ~/.claude/skills/。运行环境只要 Node 18 以上；ffmpeg 可选，只在导出 GIF / MP4 预览时用到。

它负责四件事

  1. 先找现成的。node tools/list.mjs <关键词> 按 id、名称、标签和描述搜索。Skill 明说：大多数需求其实是“现成特效 + 不同参数”，比如蓝色火焰就是把火的 palette 换成冰的色阶。
  2. 放进游戏。JS 游戏直接用代码；其他引擎导出图集，按 JSON 里的 meta.pixelfx.pivot 设锚点、最近邻过滤、不压缩、按 fps 播放。Skill 还提醒：光晕会被“烘焙”成带透明度的颜色，在暗场景里看起来像叠加光，亮场景要换配色或放在暗层上。
  3. 做新的。先读 docs/AUTHORING.md（特效的接口约定、绘图 API 与质量标准），再走五步循环（见下节）。
  4. 移植成原生代码。游戏不能跑 JS、图集又不够用（比如特效要跟着移动目标，或每个实例颜色不同）时，照着 JS 原版移植，保留双缓冲、4×4 Bayer 抖动阈值和色阶查表，最后把 JS 原版和移植版并排渲染对比。

Skill 的核心：起稿—渲染—看—改

SKILL.md 开头一句话概括了它的立场：“一次性提示词做出来的特效都很平庸；起稿、渲染、亲眼看、再改，才能做出好的。” 这个方法来自 Hugo Duprez，三条原则是：代码是黏土、相信自己的眼睛、给足参考。

关键在于“看”：Agent 不是凭想象写代码，而是每次渲染出一张接触印样（contact sheet，把动画按时间抽帧排成网格的 PNG），用读图能力去看它，再决定改哪里。做新特效的五步：

  1. 用一句话说清楚，带美术方向：是什么、怎么动、什么配色、多长时间。例如：“冰霜新星：冰晶从脚下向外成环爆开，中心一帧白闪，碎片旋出，地面结霜后慢慢消退。”
  2. 找参考。在库里搜最接近的两三个特效，读它们的代码借技法；也去看 Hugo Duprez 的同类特效——那是质量线：同样大小下，他的细节、光感、生气比你多，你的就还没做完。
  3. 起稿。node tools/new.mjs <类别>/<名字> 生成一个能跑的起点。方向不确定时，写 3–5 个真正不同的草稿（-a 到 -e），全部渲染，逐张看过再选；用户在场就给他看最好的两三个。
  4. 看、判断、修。打开接触印样，像挑剔的像素画师那样挑毛病，只修最差的那一处，再渲染。最少三轮，重头戏更多。
  5. 检查。node tools/check.mjs <id> 会查出画出画布、一次性特效结束时没清空、循环接缝、未使用种子的随机数、过慢的帧，一直修到全部通过；没选中的草稿删掉。

Skill 里还有一张“看到什么 → 怎么修”的对照表，几乎是一份像素特效的审美清单，摘几条：

看到的问题常用修法
原尺寸下糊成一团颜色更少、轮廓清楚、一个视觉焦点、形状更大
发飘、没力度快进慢出的缓动、1–2 帧白色“英雄帧”、总时长缩短
僵硬、机械每个粒子都有差异（大小、速度、延迟、寿命），加次级运动（火星、烟、碎屑）
发灰、过曝光晕减弱、边缘色阶加深，白色只留给最热的核心
平单侧打光：左上更亮、右下暗一阶，底部加一阶暗色
平滑渐变、像矢量图颜色用硬色阶，柔和只留给光和半透明的烟

另外几条硬约定：有方向的特效朝右，地面特效站在 y = 0，所有随机数来自种子（不许用 Math.random）；通用母题可以，不许复刻某个具体游戏的精灵、角色或标志。

本站实测

为核对 README 的说法，本站浅克隆了仓库（未安装任何依赖），在 Node 22 下跑了几条命令。⚠️ 本站没有在 Claude Code 里实际安装并驱动这个 Skill 做新特效，下面只验证了 Skill 依赖的命令行工具。

  • node tools/list.mjs 报告 232 个特效；node tools/list.mjs frost 返回 10 个相关特效。
  • node tools/render.mjs ice/frost-nova 不到 1 秒生成 103 帧的接触印样（下图）；check.mjs 结果 “1 pass, 0 fail”。
  • --sheet 导出 frost-nova.png + frost-nova.json，JSON 的 meta.pixelfx 写着 fps 30、单次播放、帧尺寸 288×192、锚点 (144, 150)、9 列——与 README 描述一致。
  • 用 README 里的那串蓝紫色 palette 重渲 fire/torch，同一支火把变成冷色火焰，代码一行没改。

工作原理

  • 两种特效，都不用图片。“纯”特效导出 draw(p, t, o)，第 t 秒的画面只由 t 决定，所以循环首尾无缝；“模拟”特效导出 create(o)，以 120 Hz 步进真实的粒子、碎屑和光源，帧率变了，火星的弹跳、烟的翻滚也不变。
  • 两块缓冲。color 放像素（不透明、抖动或真正半透明），light 放叠加光晕。热的东西看起来热，靠的是光缓冲。
  • 一切都有种子。同一个种子，第 40 帧永远是同一张图。
  • 局部坐标。特效围绕自己的原点作画，由 painter 负责摆放、镜像、旋转；有个 24×38 的“替身小人”用于状态、光环和受击类特效。
  • 与 Sprite Fusion 同一帧格式（{ w, h, ox, oy, color, light }），两个库的特效可以画进同一帧。

用一个。

在浏览器游戏里（canvas、Phaser、PixiJS、Kaplay、three.js），直接用代码。没有依赖。

import { createFrame, clearFrame, createFx, composite } from "pixelfx";
import * as frostNova from "pixelfx/fx/ice/frost-nova";

const frame = createFrame(320, 180);                   // 你游戏的像素分辨率
const img = new ImageData(320, 180);
const fx = createFx(frostNova, { x: 160, y: 140 });   // 还可以传：flip、angle、seed、palette、light……

function tick(dt) {
  fx.update(dt);
  clearFrame(frame);
  fx.draw(frame, "back");                              // 画在角色后面的部分
  drawCharacters();
  fx.draw(frame, "front");
  composite(frame, img.data, backgroundColor);         // 先合成颜色，再叠加光
  ctx.putImageData(img, 0, 0);                         // 用 image-rendering: pixelated 放大
}

用 npm i github:patch-gg/pixelfx 从 GitHub 安装，或者把 src/core 和你要的特效复制过去。

在任何引擎里（Godot、Unity、GameMaker、Defold、LÖVE、Bevy），用精灵图集：

node tools/render.mjs ice/frost-nova --sheet

它会写出一张把每一帧排成网格的透明 PNG，以及一个 Aseprite 风格的 JSON（帧矩形、时长，以及 meta.pixelfx 里的 fps、是否循环、列数和锚点）。Phaser 的图集加载器和 Godot、Unity 的 Aseprite 导入器都能读它。node tools/sheets.mjs 会把整个库导出到 sheets/。

任何特效都接受 palette（一串从暗到亮的十六进制颜色），所以火可以烧成蓝色，治疗可以发粉光，不用改它的代码：

node tools/render.mjs fire/torch --gif --opts '{"palette": ["#102","#215","#43a","#8cf","#cff","#fff"]}'

node tools/new.mjs arcane/my-spell       # 一个能跑的起点（循环特效加 --loop）
node tools/render.mjs arcane/my-spell    # 写出 records/arcane/my-spell/contact.png：去看它

工作原理。

  • 两种特效，没有图片。纯特效导出 draw(p, t, o)，第 t 秒的画面只由 t 算出，所以循环首尾拼接没有接缝。模拟特效导出 create(o)，以 120 Hz 步进真实的粒子、碎屑和光源，所以无论帧率多少，火星的弹跳和烟的翻滚都一样。
  • 两块缓冲。color 接收像素：不透明的、抖动的或真正半透明的。light 接收叠加的光晕，加在最上面。热的东西之所以看起来热，靠的就是光缓冲。
  • 一切都有种子。每个随机数都来自特效的种子，所以第 40 帧每次都一样。
  • 局部坐标。特效围绕自己的原点作画；painter 负责摆放、镜像和旋转。有方向的特效朝右。一个 24×38 的替身角色用于状态、光环和受击类特效。
  • 与 Sprite Fusion 的 VFX 帧结构相同（{ w, h, ox, oy, color, light }），所以两个库可以画进同一帧。

展开 skills/pixelfx/SKILL.md 中译

〔文件头元数据〕名称：pixelfx。描述：用 pixelfx 库以代码制作像素风特效和精灵动画。库里有 232 个现成特效（火、爆炸、水、冰、闪电、科幻、近战、受击、投射物、出生与死亡、奥术、神圣、暗影、状态、自然、天气、UI、拾取、转场、小动物），可以直接放进游戏、换色、导出精灵图集或改造；另有一套“起稿、渲染、看、打磨”的循环，让新特效看起来像手绘动画。适用于：有人想要像素风 VFX、精灵动画或精灵图集、游戏“手感”（game juice）、某个具体特效（“给我的法师一个冰霜新星”“一个拾取金币的闪光”），想在 Godot、Unity、Phaser 或 canvas 游戏里使用或导出 pixelfx 特效，或者想让自己的像素特效更好看。许可：MIT。兼容性：Node 18 或更新；ffmpeg 可选（用于 GIF 和 MP4 预览）。

pixelfx

以代码表达的像素特效。每个特效是一个文件 src/fx/<类别>/<名字>.js，画进两块缓冲：color（像素：不透明、抖动或真正半透明）和 light（叠加光晕）。没有图片，所以特效可以实时播放、换色、镜像、换种子，并渲染成任何引擎可用的精灵图集。

方法是 Hugo Duprez 的（《How to make (good) pixel art effects with Claude》）：代码是黏土，相信你的眼睛，给足参考。一次性提示词只能做出平庸的特效。你渲染出来、看过、再打磨的草稿，才能变成好特效。

开始之前

  1. 在一个 pixelfx 检出目录里工作。如果当前工作目录里没有 tools/render.mjs，就在项目旁边克隆一份：git clone https://github.com/patch-gg/pixelfx。不需要安装步骤：这些工具只用 Node。
  2. 确认能跑：node tools/render.mjs fire/torch 会写出 records/fire/torch/contact.png。用你的读图工具打开这张 PNG。从现在起，你就是通过接触印样来看每一个特效的。

1. 先找现成的特效

node tools/list.mjs <关键词> 会搜索 id、名称、标签和描述（node tools/list.mjs frost、node tools/list.mjs slash loop）。docs/CATALOG.md 按类别列出全部。把候选都渲染出来，看过再选。大多数需求其实是某个现成特效加上不同的参数：

  • palette：主色阶，从暗到亮的十六进制字符串。可以用 src/core/color.js 里任意一条 PAL 色阶（fire ember lava smoke dust ice water electric volt poison holy heal arcane shadow blood earth stone gold leaf wood metal bone neon cyber matrix candy night），也可以自己配。蓝色的火就是 {"palette": PAL.ice}。
  • seed 得到另一个不同但等价的版本；flip 朝左；angle 旋转；light（0 到 1 以上）控制光晕强度；外加每个特效在 meta.options 里自己的参数（尺寸、数量、半径、文字、高度……）。
  • 不改代码也能试参数：node tools/render.mjs fire/torch --opts '{"palette":["#102","#215","#43a","#8cf","#fff"]}'。

2. 放进游戏

JS 或 TS 写的 Canvas / WebGL 游戏（原生 canvas、Phaser、PixiJS、Kaplay、three.js）：直接用代码。它没有依赖；把 src/core 和需要的特效文件复制过去，或者依赖这个仓库。

import { createFrame, clearFrame, createFx, composite } from "pixelfx";   // src/core/index.js
import * as frostNova from "pixelfx/fx/ice/frost-nova";                   // src/fx/ice/frost-nova.js

const frame = createFrame(320, 180);            // 游戏的像素分辨率；ox、oy 随相机滚动它
const img = new ImageData(320, 180);
const fx = createFx(frostNova, { x: hero.x, y: hero.y, flip: hero.facing < 0 });

// 每个 tick
fx.update(dt);
clearFrame(frame);
fx.draw(frame, "back");    // 画在角色后面的部分
drawCharacters();          // 你自己的精灵，或者自己把它们画进 frame.color
fx.draw(frame, "front");
composite(frame, img.data, background);   // 颜色叠在背景上再加光；传 null 则透明
ctx.putImageData(img, 0, 0);              // 然后用 image-rendering: pixelated 放大画布
if (fx.done()) removeIt();               // 一次性特效会自己结束；fx.stop() 让循环特效淡出

多个特效可以共用一帧。在 WebGL 引擎里，每帧把合成好的 RGBA 上传到一张纹理；或者一次性把特效渲染成精灵图集（见下），像别的动画一样播放。

任何引擎（Godot、Unity、GameMaker、Defold、LÖVE、Bevy、Construct）：导出精灵图集。node tools/render.mjs ice/frost-nova --sheet 会写出 records/ice/frost-nova/frost-nova.png（排成网格的透明帧）和 frost-nova.json（Aseprite 风格的帧数据，所以 Phaser 的图集加载器、Godot 和 Unity 的 Aseprite 导入器以及大多数工具都能读；meta.pixelfx 里有 fps、是否循环、帧尺寸、列数和锚点）。把锚点设为 meta.pixelfx.pivot（特效的原点，比如脚底），用最近邻过滤、不压缩导入，按 meta.pixelfx.fps 播放。光晕会被烘焙进图集，成为带透明度的颜色，叠在暗场景上读起来像叠加光；亮场景请渲染一个换色版本，或者把特效放在一个暗的图层上。

整个库：node tools/render.mjs <类别> --sheet 一次导出整个类别。

3. 做一个新的

先读 docs/AUTHORING.md：那是接口约定（meta；纯特效用 draw(p, t, o)，模拟特效用 create(o)；局部坐标；无缝循环；结束时清空）、工具箱、painter API 和质量标准。然后：

  1. 用一句话说出来，带美术方向：它是什么、怎么动、什么配色、什么节奏。“冰霜新星：冰晶从脚下向外成环爆开，中心一帧白闪，碎片旋出，地面保持结霜然后消退。”
  2. 在库里找参考：node tools/list.mjs <关键词>，然后读最接近的两三个特效文件，借用它们的技法（火星、烟、碎屑用 src/core/sim.js 里的 Particles 和 Bits，半透明体积用 p.disc，无缝粒子用 cycle，火焰和水用 tileFbm 滚动）。也去看看 Hugo Duprez 的特效里最接近的那个：它们是质量线。如果同样的屏幕尺寸下他的有更多细节、光感或生气，你的就还没做完。
  3. 起稿。node tools/new.mjs <类别>/<名字>（循环特效加 --loop）给你一个能跑的文件。方向还没定的时候，写 3 到 5 个真正不同的草稿（<名字>-a.js 到 -e.js），全部渲染（node tools/render.mjs "<类别>/<名字>-*"），每张接触印样都看过再选。如果用户在，给他看最强的两三个（--gif 能做出可分享的动图）。
  4. 看、判断、修。渲染，打开 records/<id>/contact.png，像一个挑剔的像素画师那样评判。修最差的那一处，再渲染。最少三轮；重头戏要更多。--all 显示每一帧，--mp4 以全速显示动态。
  5. 检查。node tools/check.mjs <id> 能抓到画出画布、一次性特效结束时没清空、循环接缝、未用种子的随机数和过慢的帧。一直修到干净通过。没留下的草稿删掉。

该看什么，以及通常的修法：

你看到修法
原尺寸下糊成一团更少的颜色、清楚的轮廓、一个焦点、更大的形状
斑点：形状内部孤立的噪点像素噪声阈值放宽些，用 at() 量化，小形状上不加噪声
发飘，没力度快进慢出（ease.outQuart / outExpo），1 到 2 帧白色英雄帧，缩短总时长
僵硬或机械每个粒子都有变化（大小、速度、延迟、寿命），加次级运动（火星、烟、碎屑）
发灰过曝光晕减弱（k 取 0.2 到 0.5），边缘色阶更暗，白色只留给最热的核心
平从一侧打光：左上更亮，右下暗一阶；底部加一阶更暗的色阶
平滑渐变，矢量感颜色用硬色阶；柔和只留在光和半透明的烟里
该是烟的地方成了棋盘格用 SMOKE、VAPOUR 或 DUST 粒子，或 p.disc：真正半透明，上面再打光
循环回绕处有接缝cycle、loopNoise(phase)、整格的 tileNoise 滚动、sin(phase * TAU * n)
一次性特效突然消失在 t = duration 之前让它缩小、抖动消散或落下

有方向的特效朝右，地面特效站在 y = 0，角色特效包住 o.actor（一个 24 × 38 替身角色的遮罩和像素），并且任何地方都不用 Math.random。通用母题可以；绝不复刻某个具体游戏的精灵、角色或标志。

4. 用原生代码代替 JS

如果游戏跑不了 JS，而精灵图集又不够（比如特效要跟随移动目标，或者运行时每个实例要不同颜色），就移植这个特效。纯特效是时间的函数；模拟特效在 src/core/sim.js 里步进粒子。保留双缓冲的思路、用于抖动透明度的 4×4 Bayer 阈值，以及色阶查表。把 JS 原版和你的移植版并排渲染，检查二者一致。
