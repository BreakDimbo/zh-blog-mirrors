这是什么

这是 Lex Fridman Podcast 的非官方中文导航站。作者是向阳乔木，一个人做，没有广告也不收费。页脚写明它与 Lex Fridman 和节目方没有隶属关系。首页的一句话是：「把世界上最好的长访谈，用中文认真读一遍。」

Lex 的节目每期动辄三五个小时。中文读者面对的问题有两个：英文听力门槛高，几百期里也不知道该听哪期。这个站做了三件事：

  • 每期一页：每期有固定网址，页面上有官方音频播放器、YouTube 视频（点击才加载）、中英双语标题、嘉宾简介和英文文稿。
  • 中文精读：AI 读完整场访谈后改写的中文长文。按免责声明的说法，它是「二次创作，并非官方翻译」，像有人替你先听了一遍再讲给你。以 #494 黄仁勋为例，精读约 1.5 万字，阅读约 34 分钟，分成近 30 个小标题。
  • 找得到：支持全文搜索，按年份列出目录，也提供 RSS 全文订阅。

怎么用

  1. 先看最新或筛选：首页按「最新」排序，可以切到「中文精读」，只看有精读的单集。顶部的搜索框可按嘉宾、话题或期数查找，按 / 或 ⌘K 就能调出来。搜索结果有对应网址，可以直接分享。
  2. 按年份浏览：单集目录按年份列出全部 506 期，有精读的标着「精读」。
  3. 读单集：单集页上方是播放器，支持倍速记忆、±15 秒跳转和断点续听。下面分「中文精读 / 英文文稿」两个标签。文稿注明来源：官方 Transcript、Kaggle 公开数据集存档或机器转写。点时间戳可以跳到音频对应位置。宽屏时有目录侧栏，还可以调字体和字号。
  4. 机器可读：每篇精读都有纯 Markdown 版，在单集网址后面加 index.md 就行，例如 /ep/jensen-huang/index.md。llms.txt 列出了全部单集和简介。
  5. 订阅：RSS 推送最新 20 篇精读的全文。站点也能「添加到主屏幕」当作应用打开，读过的文章离线也能看。

构建与设计：值得注意的地方

  • 纯静态，构建只用 Python 标准库：tools/build.py 一条命令生成 506 个单集页、sitemap、llms.txt 和 RSS，没有第三方依赖。元数据（lex-master.json、translations.json）和精读全文（site/zh/）都提交在仓库里，clone 下来就能构建出完整的站。
  • 每天自动追新：sync_new.py 每天和官方 RSS 对账。遇到新的一期，它会补元数据和 YouTube ID，翻译标题，补上文稿，然后构建并用 rsync 部署。文稿分三级来源，优先级为官方 Transcript > 本地 Whisper 转写（mlx-whisper）> 存档。
  • 精读批量生成：gen_zh.py --watch 常驻运行，每 10 分钟扫描一次新文稿，每生成 30 篇自动部署一次。它会检查生成稿里有没有被禁止的翻译腔句式，不合格就带着反馈重写；多个模型按质量动态排序。默认通过作者自己的 Magpie LLM 网关调用，密钥存在 macOS 钥匙串里。
  • 版权边界写进了设计：站点不托管任何媒体文件。音频在线播放官方播客 RSS 渠道（blubrry）的文件，视频和原始文稿都只给链接。英文文稿不进仓库，README 明确说不接受和托管媒体有关的改动。
  • 对 SEO 和 AI 友好：页面带 JSON-LD（包括 SearchAction）。RSS 是全文，enclosure 长度是真实值，并支持 ETag/304。站点提供 llms.txt 和 Markdown 版正文，robots 主动欢迎 AI 抓取。这和很多中文内容站的做法相反，作者的目标显然是被检索、被引用。
  • 报纸式版面：报头带日期线，标题用大号衬线字（Libre Caslon Text + Noto Serif SC），标题下有双线分隔，再往下是一行小字统计，中英标题上下排，英文用斜体。界面克制，以黑白为主，强调色只用于少量元素（如「最新精读」标签），也支持深色主题。字体走 fonts.googleapis.cn 镜像，照顾到国内访问。
  • 阅读细节：会记住阅读进度和「继续收听」，视频要点击才加载，宽屏有目录侧栏，可调字体和字号，能装成 PWA 离线阅读。访问统计用作者自建的 umami。

对我们的启发

  • 「替你先听一遍」比逐字翻译更有用：三五小时的访谈，逐字翻译没人读。按主题改写的长文配上小标题，读者真的能读下去。我们做长文导读时可以学这个分寸：结构跟着论点走，引语要标出说话人，并且声明以原文为准。
  • 先把版权边界想清楚，再写代码：媒体只链接不托管，文稿不进仓库，精读标明是 AI 二次创作，许可写清只管代码，再加一页免责声明和联系方式。这套做法可以直接拿来对照检查我们自己的镜像站。
  • 同时为机器设计：每篇都有 Markdown 版、一份 llms.txt 全量索引、全文 RSS，robots 也明确放行。内容站在「被 AI 引用」的时代可以这样设计。我们的文库也可以考虑提供 index.md 和 llms.txt。
  • 流水线做成常驻任务，并带自动质检：自动追新、三级文稿来源、禁用句式校验后带反馈重试、攒够一批再部署，这几样让一个人也能维护 500 期规模的内容。
  • 一个人也能做出编辑级的设计：报头、双线、中英对照、克制的配色，没用花哨组件，靠字体和留白就有了「刊物感」。
