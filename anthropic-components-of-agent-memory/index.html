智能体记忆的组成：从即时笔记到后台整理

来源：Anthropic · The components of agent memory，2026-11-06；Lance Martin 撰写。核对日期：2026-11-07。本文为独立中文导读，不是全文翻译；未复制原图。

五句框架摘要

文章把智能体记忆限定为从任务和交互中获得、保存到会话之外、未来可读取的知识，不包括权重更新、单会话学习或上下文压缩。第一层是在任务现场判断显著性，保存经过验证的规则、计划与不可直接重新观测的经验，而不是事无巨细地归档状态。第二层是利用空闲时间进行 dreaming：回查原始记录、纠错、建立关联 wiki，并修补缺页和重复链接。第三层是按层级决定哪些短小记忆应预加载，哪些详细知识应留在下层按需检索。整体不是让 wiki 替代搜索，而是让来源搜索、精炼表示与针对任务的反馈循环共同工作，同时控制错误、过时与维护成本。

逐节导读

1. 写下什么，比写下多少重要

记忆是一种对未来需求的预测。作者用数据库问答评估展示从未经测试的猜测到“提出解释—检验—写入有证据规则”的学习闭环；只保存失败的硬规则反而削弱部分模型收益。对较旧模型，提醒读取笔记、主动测试猜想有帮助；对较强模型，过细地规定什么值得记忆可能限制判断。

2. 不要把随时可观察的状态当经验

宝可梦案例中，过度记录遭遇、物品与位置的模型产生庞大且快速过时的目录。另一种方案用少量文件保存当前目标、路线计划与经过尝试的策略。⚠️ 这些是作者报告的模型案例，不构成“文件少必然成绩好”的因果证明；模型能力也不同。

3. dreaming 的六类工作

  • 校正：把记忆与会话记录对照，纠正地理位置等错误。
  • 建立表示：将源文档组织成有链接的 wiki，使跨文件关系可导航。
  • 上移：把高价值、普适的短笔记放进自动注入层，细节留在下层。
  • 聚焦：根据目标或评估失败调整整理方式，而非使用万能摘要模板。
  • 补洞：查找不存在的页面、错指链接和遗漏的索引。
  • 持续维护：在即时可用性与离线算力、时效性之间权衡。

4. wiki + 搜索，而不是 wiki 取代来源

Anthropic 自报的 Stainless 内部文档实验涵盖约 35 万文件、4.2 亿 tokens 和 25 道问题。增加整理轮次后，wiki 单独回答的评分从 13% 升至 48%；wiki 加搜索从 54% 升至 61%，仅搜索为 53%，并报告每问节约约两万 tokens。⚠️ 这是作者的内部评估，本文未复现；这些数字不是任意资料库的保证。

5. 有些任务需要精确保留，不宜概括

涉及多文档合并和推理时，wiki 的关系整理更有价值；单文档文字检索可解决的任务未出现明确优势。法律合同案例中，共享汇总表产生遗漏与并发覆盖；调整为每份合同由单一 agent 负责一页并准确保留条款后，作者报告覆盖事实从 41/57 提升至 57/57。⚠️ 这是任务特定结果，不能解释为“所有 wiki 都该逐字引用”。文中也展示 wiki 膨胀到超过原始资料、没有产生抽象价值的失败例。
