AvatarScript：写一段带“导演批注”的文字，得到会对口型、会演戏的头像视频

Turn an avatar and text into a lip-synced, acted video

仓库：github.com/receptron/avatarscript · 组织 receptron（MulmoCast、GraphAI 的开发方）· npm：avatarscript · MIT 许可

一句话：给它一个“头像包”（一张拆好图层的插画）和一段文字，文字里用 [emotion:happy]、<nod>、[pause:300ms] 这样的批注写好情绪、动作和停顿，它就调用 TTS 合成语音、算出每个字的发音时刻，再逐帧渲染出口型同步、会点头会惊讶的视频。

它是什么

AvatarScript 想解决的是“让一个头像替你开口说话”这件事里最费工的部分：口型对齐、表情切换、动作卡点。它把流程拆成三件可以单独检查、单独修改的东西：

头像包 + 文字 ──► AvatarScript (.avs) ──► 编译器 + TTS ──► score.json + 音频 ──► video.mp4
  1. 标准头像包（avatar.json）：一个头像必须声明什么（运行时、资源、情绪/动作能力、默认声音、版权），才能在不关心它内部怎么做出来的前提下被驱动。
  2. 脚本语言（.avs）：就是你要说的原文，加上行内“导演批注”——情绪、动作、停顿，未来还有视线与重音。设计上由 LLM 来写、人来改。
  3. 编译器与渲染器：合成语音，把脚本按语音的实际时间轴解析成带时间戳的乐谱（score），再用无头 Chrome 逐帧驱动头像引擎，管道给 ffmpeg 出片。

第一个运行时是 shinshin86（Yuki Shindo）的 mesh-avatar-studio 里的 2D 网格头像引擎 mesh-avatar：它能把一张插画变成会眨眼、会转头、有表情和元音口型的 2D 网格头像，AvatarScript 已把它打包在 npm 包里，装完即可渲染。

五个要点

  1. “表演交给 LLM，时间交给代码”。设计目标里写得很明白：LLM 决定情绪、手势、视线、重音这些表演，确定性代码决定时间，从不让 LLM 输出时间戳。脚本里的锚点是纯文本中的字符偏移，所以对日文、中文这种没有空格的语言同样成立。
  2. 原话不改一个字。去掉批注后的纯文本必须与输入完全一致，否则编译器拒绝；TTS 若“多念了词”（比如把风格提示念出来），会通过对齐检测到、重试一次，仍不对就报错。
  3. 一个 TTS 接口，三家供应商。createTts({ provider, … }) 统一返回 24 kHz 单声道采样 + 每个字符的 {start, end}。ElevenLabs 自带字符时间戳（再对照音频校正）；OpenAI、Gemini 只给音频，就在本地用 wav2vec2 音素模型（ONNX）做强制对齐——与 ElevenLabs 自带时间对比，中位误差 19 ms（一帧模型 20 ms）。
  4. 可复现、可审阅的每一步。脚本、乐谱、音频、视频都是落盘文件；语音按段缓存，改一个动作或一句话不会重新请求整篇；渲染带随机种子，同一乐谱 + 种子 + 头像得到同一视频。
  5. 为 MulmoCast 而生。它首先是 Node 库，CLI 只是薄壳。compileTimeline 接收宿主已经合成好的音频（MulmoCast 自己做 TTS），只负责“加一张会说话的脸”，可输出透明背景的 WebM 头像轨道叠到幻灯片视频上。

工作原理：口型怎么对上

  1. 每段文本用 ElevenLabs /with-timestamps（默认 eleven_v3，并带 language_code）合成，拿到每个字符的发音时刻。
  2. 对照音频校正时间：测出起音、收音和标点处的静音，把字符时间轴拉伸对齐（v3 在情绪标签后可能晚 0.4 秒起音）。
  3. 字符变成视素（viseme）：日文经 kuromoji 读音转成假名音拍，拉丁字母按拼写规则，其他字符走通用开/合。
  4. 渲染器在无头 Chrome 里逐帧驱动网格引擎，固定随机种子，帧流管道给 ffmpeg。

Today I'd like to show you a new way to turn text into video.
[emotion:surprised] You just write the words, and I speak them! <surprise>

现状与边界

早期但端到端可用：三家 TTS、日英口型、情绪与动作、MP4 / 透明 WebM / ProRes 输出、字幕。还没做的：自动写脚本的 LLM 步骤、视线与重音的渲染（语法已能解析）。v1 不做音频输入（录音驱动）、实时流式和 3D 头像。另一个值得注意的细节是许可意识：设计阶段放弃了 Meta 的 MMS 对齐器，理由是其权重为 CC-BY-NC；头像包的 license 字段会随渲染写进元数据。

对我们的启发

  • “代码即影片”的又一种形态。本站收录过用代码画水墨、用 Claude 渲染城市史的项目；AvatarScript 则把“出镜讲解人”也变成了一份可 diff 的文本文件——改一句台词、换一个动作，只重算那一段。

AvatarScript

把一个头像和一段文字变成口型同步、带表演的视频：

avatar package + text ──► AvatarScript (.avs) ──► compiler + TTS ──► score.json + audio ──► video.mp4

AvatarScript 定义了一种标准头像包、一种用于指挥头像说话、情绪和手势的脚本语言，以及生成视频的编译器和渲染器。第一个运行时是网格头像引擎，即 mesh-avatar-studio 中的 mesh-avatar。设计与里程碑见 PLAN.md。

状态

尚处早期，但已端到端可用：来自 ElevenLabs、OpenAI 或 Gemini 的语音，日语和英语口型同步，情绪和动作，用网格引擎渲染为 MP4。尚未实现：编写脚本的 LLM 步骤，视线与重音的渲染。

安装

需要 Node.js 22.18+ 和 ffmpeg。包内已含网格头像引擎，渲染无需其他任何东西。

npm install avatarscript
npm install onnxruntime-node             # 仅用于 --tts openai 或 gemini（通过对齐获取时间，约 290 MB）
echo "ELEVENLABS_API_KEY=..." > .env    # 从环境变量或 ./.env 读取

命令行

npx avatarscript make --avatar https://raw.githubusercontent.com/receptron/mulmocast-media/main/avatars/ani \
  --script example:hello-ja --tts elevenlabs -o out/hello-ja.mp4

--script example:<name> 读取包内附带的示例脚本（examples/*.avs：hello-ja、hello-en、subtitles-ja）；否则 --script 接受你自己的 .avs 或纯 .txt 文件。

npx avatarscript 在本仓库的克隆目录中无法使用。npx 找到的是项目本身而不是已发布的包，而一个包永远不会被链接进它自己的 node_modules/.bin，所以即使执行过 yarn build，也会报 sh: avatarscript: command not found。请在任何其他文件夹中运行，或在克隆目录中使用以下之一：

  • yarn avatarscript make ...：从源码运行 CLI
  • node dist/cli.js make ...：yarn build 后运行构建好的 CLI
  • npx avatarscript@latest make ...：从 npm 获取已发布的包

这会写出 out/hello-ja.wav、out/hello-ja.score.json 和 out/hello-ja.mp4。合成的语音按段缓存在 out/.tts-cache/，所以修改动作或某一句话不会重新请求整篇脚本。--tts mock 用一个嗡嗡作响的替身声音离线运行整个流程。各步骤也可以用 compile 和 render 分开运行；运行 npx avatarscript --help 查看全部选项（声音、模型、尺寸、帧率、背景、种子）。

--avatar 接受一个 mesh-avatar-studio 项目文件夹（rig.json + built/）或一个带 avatar.json 清单的文件夹，可以在磁盘上，也可以是 http(s) URL。仓库包含一个示例头像 avatars/ani（不在 npm 包中）；上面的 URL 是同一个头像，发布在 mulmocast-media 中，因此无需克隆即可使用。

从 URL 加载时，包里的小 JSON 文件每次都会获取，图片则按头像的每次构建缓存在 ~/.cache/avatarscript/avatars/（或 $AVATARSCRIPT_AVATAR_DIR），因此头像更新后会重新获取。只获取包文件夹内的文件，每个最多 32 MB，且图片必须是 PNG。重定向只在同源内跟随，所以请使用直接的文件 URL（raw.githubusercontent.com，而不是 github.com/.../raw/...）。在 URL 中用某个提交代替 main 即可锁定版本。只有文字会发送给 ElevenLabs；头像图片留在本地，渲染页面没有网络访问。

库

examples/make-video.ts 是一个完整、可运行的示例。简而言之：

import { loadAvatar, parseScript, compile, render, createTts, toWav } from "avatarscript";
import { writeFile } from "node:fs/promises";

const avatar = await loadAvatar("path/to/avatar"); // 或头像文件夹的 https:// URL
const tts = createTts({ provider: "elevenlabs", cacheDir: "out/.tts-cache" }); // key 取自 ELEVENLABS_API_KEY
const { score, audio } = await compile(parseScript("[emotion:happy] Hello! <nod>"), tts, { lang: "en", audioName: "hello.wav" });
await writeFile("out/hello.wav", toWav(audio));
await render({ avatar, score, audioPath: "out/hello.wav", out: "out/hello.mp4" });

compile 返回带时间的乐谱和音频；render 把乐谱变成视频。ScoreSchema 和 AvatarManifestSchema（zod）用于校验从文件读入的乐谱和清单。

已有的语音（compileTimeline）

自己做文字转语音的宿主（MulmoCast 就是）把现有音频文件放到时间轴上；不调用 TTS，时间来自强制对齐（需要 onnxruntime-node）：

import { avatarAspect, compileTimeline, loadAvatar, render, toWav } from "avatarscript";

const { score, audio } = await compileTimeline(
  [
    { text: "みなさん、こんにちは！", audio: "beat0.mp3", start: 1.0, emotion: "happy", motions: [{ motion: "nod", at: "こんにちは" }] },
    { text: "スライドの上で説明します。", audio: "beat1.mp3", start: 4.2 },
  ],
  { lang: "ja", duration: 9, view: { background: "transparent" } },
);
await writeFile("voice.wav", toWav(audio)); // 让头部随声音运动
const avatar = await loadAvatar("path/to/avatar"); // 或头像文件夹的 https:// URL
const height = 446, width = Math.round(height * avatarAspect(avatar.rig) / 2) * 2;
// 一条连续、透明的头像轨道，只有画面，用于叠加到另一段视频上
await render({ avatar, score, audioPath: "voice.wav", audio: false, out: "avatar.webm", width, height });

motions[].at 指定文本中的词：动作从说到这些词的地方开始。avatarAspect 给出头像的宽 ÷ 高，用于设定一条只容纳头像的轨道尺寸。对于叠加在其他视频上的轨道，请同时给 avatarAspect(rig, 0) 和 render 传 padTop: 0：有些 rig 会裁掉图像平直的上边缘，只有头像顶到画面上沿时这条边才会被隐藏。（用 avatar-y/avatar-scale 放在画面内部时，整张图像本来就会完整显示。）在 ffmpeg 中用 -c:v libvpx-vp9 解码 WebM 以保留其 alpha 通道。

文字转语音

所有供应商只有一个 API：createTts({ provider, model?, voice?, apiKey?, options?, cacheDir? })。供应商是一个参数，它原生返回的任何内容都会被规范化，所以供应商或模型变化时应用代码不必改动：

  • synthesize(request) 总是返回 Speech：采样率为 SPEECH_SAMPLE_RATE（24 kHz）的单声道采样，以及文本中每个字符一个 { start, end }。其他采样率会被重采样；与文本不匹配的时间信息视为错误。
  • model 和 voice 默认取供应商的默认值；apiKey 默认取其环境变量。供应商特有的设置放在 options 中，由该供应商检查。
  • 目前的供应商：
    providerkey时间信息语音情绪options
    elevenlabsELEVENLABS_API_KEYElevenLabs 自带，并对照音频校正v3 音频标签emotionTags、seed
    openaiOPENAI_API_KEY强制对齐instructions（gpt-4o-mini-tts）instructions、emotionInstructions、speed
    geminiGEMINI_API_KEY强制对齐导演备注instructions、emotionInstructions
    mock—精确，但是编造的——
  • OpenAI 和 Gemini 只返回音频。由于文本已知，其时间信息通过强制对齐求得：一个音素模型（wav2vec2-lv-60-espeak-cv-ft，Apache-2.0，以 ONNX 形式）通过 onnxruntime 在本地运行，其音素被归并为几个大类，再把文本（来自 kuromoji 读音的假名，或拼写）拟合上去。在 8 个句子上对照 ElevenLabs 自带的时间测量：中位误差 19 ms（模型一帧为 20 ms）；79%（日语）和 91%（英语）的字符误差在 50 ms 以内。
  • 模型（635 MB）只从 Hugging Face 下载一次，存入 ~/.cache/avatarscript/models（或 AVATARSCRIPT_MODEL_DIR）。对齐时音频和文本都不会离开本机。
  • 说话风格（openai、gemini）：instructions 为每一句描述角色（“你是一个精力充沛的 7 岁男孩。用高亢的小孩嗓音。”），后面接上该句情绪对应的风格——默认的，或你在 emotionInstructions 中自定义的（{ "happy": "…" }）。Gemini 的提示词总是 ### DIRECTOR'S NOTES（风格）后接 #### TRANSCRIPT（文本），Gemini 会遵循这种形式而不把它念出来；在 gemini-2.5-flash-preview-tts 上单独发送文本时，如果是问句会失败。
  • 没有说出该文本的语音——供应商念了多余的词，例如它的指令——会从对齐中被检测出来，重新请求一次，否则报错。
  • 以 503 或 429（模型过载）响应的 Gemini 请求会重试三次，间隔 1、2、4 秒。

头像可以在 avatar.json 中按供应商指定默认声音、模型和供应商选项，让角色的说话风格随头像一起走：

"voice": {
  "gemini": { "voice": "Puck", "options": { "instructions": "You are an energetic 7-year-old boy…" } },
  "openai": { "voice": "verse", "options": { "instructions": "…", "emotionInstructions": { "happy": "…" } } },
  "elevenlabs": { "voice": "<voice id>", "model": "eleven_v3" }
}

CLI 的 --voice 和 --model 会覆盖头像中的设置；头像的 options 则原样使用。

脚本

脚本就是要说的文字，加上行内的指挥批注。纯 .txt 文件按原样朗读。

---
lang: ja
---
[emotion:happy] みなさん、こんにちは！<nod> アニです。
[pause:300ms]
[emotion:surprised] テキストを書くだけで、私がしゃべるんです！<surprise>

（示例台词大意：“大家好！我是 Ani。”“只要写文字，我就会说出来！”）

语法含义
[emotion:NAME]从此处起的情绪：neutral happy sad angry surprised relaxed；使用 eleven_v3 时，语音会获得对应的情绪标签
[pause:300ms]、[pause:1.2s]静音
<motion>在下一个被说出的字符处播放一个动作（若在行尾：在该行结束时）。网格头像：nod tilt think giggle surprise shy no wink greet 以及待机动作
[gaze:left]、*word*能解析，尚未渲染
\[ \< \* \\字面字符
front matterlang（默认：根据文本检测）

字幕每次显示一句，按语音计时；乐谱总是带有这些 captions，即使不绘制。透明背景需要能保留 alpha 的输出格式：-o video.webm（VP9）或 -o video.mov（ProRes 4444）；MP4（H.264）会被拒绝。按字体族名指定的字体必须安装在渲染视频的机器上（Linux 通常需要 Noto CJK 来显示日文）；字体文件则总是可用。

口型同步如何工作

  1. 每一段都用 ElevenLabs /with-timestamps 合成（默认模型 eleven_v3，带 language_code），它会报告每个字符何时被说出。
  2. 对照音频校正时间：测量语音的起止点以及标点处的静音，并拉伸字符时间轴使之匹配。（v3 的时间在情绪标签之后可能晚开始最多 0.4 秒。）
  3. 字符变成视素：日语经由假名音拍（汉字读音来自 kuromoji），拉丁文字的单词经由拼写规则，其他一切经由通用的张/合。
  4. 渲染器在无头 Chrome 中逐帧驱动网格引擎，使用固定种子使渲染可精确重复，并把帧通过管道送给 ffmpeg。

开发

从源码运行（node src/cli.ts …）时，会从 mesh-avatar 开发依赖中打包引擎，该依赖在 package.json 中锁定到确切版本。要在发布前试用引擎改动，把 --engine <dir> / AVATARSCRIPT_MESH_ENGINE 指向一个 mesh-avatar-studio 检出目录。

yarn install
yarn format   # Prettier
yarn lint     # ESLint，包括类型感知规则
yarn test
yarn typecheck
yarn build    # dist/，包括从 mesh-avatar 打包的引擎
scripts/smoke.sh avatars/ani   # 打包、安装、渲染（与 CI 相同）

CI（.github/workflows/ci.yml）在 Ubuntu 和 macOS 上运行 Prettier、ESLint、类型检查与构建、测试，以及上面的包冒烟测试。

yarn build 会把引擎的包版本记录在 dist/engine/source.json 中。
