导读

一个“风格样本册”式的开源仓库：作者挑了 15 种最常见的 MG（motion graphics）风格，从逐帧手绘、等轴 2.5D、扁平矢量，到包豪斯、Synthwave、液态、像素，再到 9:16 综艺花字，每种让 Claude Opus 5.5 按一段提示词写代码做出一支 10 秒成片——画面是 SVG / Canvas / WebGL / Three.js（3D 那支用 Blender），配乐和音效也是 Python 合成。每支片都公开了成片、风格说明、完整提示词和全部源码，外加渲染器、音频工具包、评审 rubric 和写新风格的模板。

  • 一份提示词 = 通用骨架 + 四段风格专属：通用部分（角色、工作方法、确定性渲染规则、工艺清单、自评、交付）15 份完全一样；每种风格只换 Style / Output / 技术路线 / 创意种子，再加一段中文的「风格特征与关键技法」——写的是可检验的参数（曲线、帧数、像素、色值），不是形容词。
  • 每帧是时间的纯函数：片子是一个网页，暴露 window.renderAt(t)；无头 Chrome 逐帧截图，audio.py 按同一张 cues.json 节拍表合成声音，ffmpeg 合成正好 10 秒的 MP4。
  • 两轮 AI 评审：另开一个 AI 按 rubric.md（七维打分 + 带时间码的修改清单）严评，再贴回去改；15 支终评 7.57–8.21 / 10。
  • 诚实的边界：同一提示词每次结果不同，一次运行通常达不到原片完成度；字体文件不随仓库；11/15 支配乐用 requirements 版本重跑会有局部差异。

怎么安装 / 怎么用

只想用提示词做一支自己的片子（最省事）：

  1. 在空文件夹里打开能写代码、能跑命令的 AI 助手（如 Claude Code）；本机装好 Node、Chrome、ffmpeg（3D 风格另需 Blender）。
  2. 打开 prompts/ 里任意一份，把「提示词」代码块整段发过去。
  3. 只改 Creative seed（故事、品牌名、文案、配色）和 Output（比如改竖屏 1080×1920）；保留 Signature features。
  4. 成片后另开 AI 用 rubric 评审提示词 打分，把意见贴回去改一轮；原片改了两轮。
  5. 想省事可以让 AI 直接复用 harness/render.mjs（渲染）和 lib/audio（mgaudio 配乐工具包）。

想跑原片源码：

git clone https://github.com/Vincentwei1021/mg-styles-15.git && cd mg-styles-15
npm install                                   # Node ≥ 22.12：three / d3 / puppeteer-core / opentype.js …
pip install -r requirements.txt               # Python ≥ 3.11：numpy / scipy / pedalboard / pyloudnorm …
python3 demos/01-flat-vector/audio.py         # 配乐 → out/audio.wav
node harness/render.mjs demos/01-flat-vector  # 逐帧渲染 → out/video.mp4（非 macOS 设 MG_CHROME=<Chrome 路径>）
python3 -m http.server 8000                   # 预览 /harness/preview.html?demo=01-flat-vector

注意：须从仓库根目录起服务；字体不在仓库里，按 assets/fonts/README.md 自备（阿里巴巴普惠体、抖音美好体、Fusion Pixel、站酷快乐体、Anton、Bebas Neue、VT323 等），否则字形会与成片不同；3D 那支步骤见 demos/04-3d-render/README.md（sim.py → scene.py → render.py → audio.py → 合成）。

对我们的启发

  • 风格包的最小单位是“四段 + 可检验特征”：把通用工艺规则抽成固定骨架，风格只写四段；“特征”必须写成能被评审对照的参数（如 overshoot 用 cubic-bezier(0.34,1.56,0.64,1)、错峰 2–4 帧），这比堆形容词稳定得多。做自己的风格库时可直接套 template.md。
  • 先节拍表、后画面与声音：cues.json 一张表同时驱动画面和 audio.py，卡点从结构上保证，而不是后期对齐。
  • 确定性是工程底线：renderAt(t) + 种子随机 + 预计算物理，让逐帧渲染、复现、AI 自检截帧都成为可能——这也是“代码即影片”能批量化的前提。
  • 评审与制作分离：rubric 要求“没做这支片的评委”、抽联系表看细节、给带时间码和数字的修改，且至少一条提升惊艳度；两轮就能从 6 分档拉到 8 分档，可直接搬进我们的视频流水线。
  • 中文场景是一等公民：综艺花字、回形针式科普、像素中文对话框都在列，提示词里明确要求地道中文与标点、无豆腐块——做中文内容的风格库可以从这 15 种起步再扩。
  • 素材合规写进提示词：只用 CC0/OFL/可商用素材、写 CREDITS.md、品牌名虚构；仓库自身也把第三方许可（VCSL 采样、Natural Earth、OFL 字形）逐项说明。

提示词全译

每份 prompts/*.md 的结构相同：开头是原片信息与「怎么用」四步（原文即中文，见上文“怎么用”），然后是一整段英文提示词。下面先给出 15 份共用的通用骨架中译，再逐一给出每种风格的专属段中译（Style / Output / 技术路线 / 创意种子；「风格特征与关键技法」原文即中文，照录）。拼起来即是每份提示词的完整中文版。

（原 README 此处为 15 支成片的动图九宫格，见上方「15 种风格卡片」；动图不转载，点卡片封面可在官方页带声音观看。）

在网页上，每种风格一节：成片、风格说明、这支片怎么做的；下面点一下就能展开完整提示词和全部源码。页面可以在中英文之间切换。

用提示词做一支

  1. 在一个空文件夹里打开能写代码、能执行命令的 AI 助手（例如 Claude Code）。本机需要 Node、Chrome 和 ffmpeg，3D 那种建议路线要用 Blender。
  2. 打开 prompts/ 里任意一份，把「提示词」那段整段发给它。
  3. 想换成自己的内容：每份提示词里只有 Creative seed 是具体故事，把里面的故事、品牌名、文案、配色换成你的；也可以把 Output 改成竖屏 1080×1920 或改时长。Signature features 那段别删，它决定这种风格能不能被一眼认出来。
  4. 想做得更好：成片出来后，另开一个 AI 用 rubric.md 评审，把评审意见贴回去改一轮。原片就是「制作 → 评审 → 修改」改了两轮。
  5. 写一种新风格：照 template.md 填四段（输出规格、技术路线、创意种子、风格特征），其余通用部分照抄。

想省事的话，可以让 AI 直接用这个仓库里的 harness/render.mjs 渲染、用 lib/audio 做配乐，不用从零搭。

Blender 只有 3D 那支要用 demos/04-3d-render/README.md

# 在仓库根目录
npm install
pip install -r requirements.txt
python3 demos/01-flat-vector/audio.py          # 合成配乐 → demos/01-flat-vector/out/audio.wav
node harness/render.mjs demos/01-flat-vector   # 逐帧渲染 → demos/01-flat-vector/out/video.mp4

部署自己的一份

  1. Fork 这个仓库，或者把全部文件（包括 .nojekyll）推到你自己的仓库的 main 分支。最大的单个文件 38 MB，在 GitHub 100 MB 的单文件上限以内，不需要 Git LFS。
  2. 仓库 Settings → Pages → Build and deployment，Source 选 Deploy from a branch，分支 main，目录 / (root)。免费账号只能给公开仓库开 Pages。
  3. 一两分钟后打开 https://<用户名>.github.io/<仓库名>/。页面会自己识别仓库地址，「在 GitHub 查看」按钮直接跳到对应文件；用自定义域名时，在 index.html 的 <meta name="repo"> 里填上仓库地址。

整个站点约 575 MB，其中视频 420 MB。GitHub Pages 的站点上限是 1 GB，每月流量软上限 100 GB；视频只有点播放才会下载。

需要知道的

  • 字体文件没有放进仓库（授权各不相同，中文字体也很大）。需要哪些、放在哪里，见 assets/fonts/README.md。缺字体时浏览器会用系统字体代替，画面里的字形会和成片不一样。
  • 同一份提示词每次做出来的片子都不一样。原片每支都经过多轮迭代，一次运行通常达不到原片的完成度。
  • 配乐脚本是确定性的：同一环境下重跑，结果每次相同。用 requirements.txt 里的版本重跑，有 4 支和成片音轨一致（误差在最低有效位以内），其余 11 支有局部差异，原因可能是数值库版本的变化。
  • 做自己的片子时，字体、图片等素材请只用允许商用的授权（CC0、OFL 等），提示词里已经这样要求。
