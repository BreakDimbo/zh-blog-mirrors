这是什么

anthropics/cwc-workshops 是 Anthropic 官方 GitHub 组织下的一个仓库，收着 Anthropic 在 Code with Claude（CwC）开发者活动上开设的动手工作坊材料。一个工作坊一个目录，现在有九个。每个目录里通常有一份带步骤的 README、可以跑的起始代码（starter）、参考答案（solution），还常带 Claude Code 用的 CLAUDE.md、Skill 或斜杠命令，学员可以让 Claude Code 当助教，一边做一边讲。

九个里有七个围绕 Claude Managed Agents（Anthropic 托管的智能体运行服务：在云端配置模型、系统提示词、Skills、MCP 工具和沙箱环境，按会话运行）。另外两个讲怎么用 Claude Code：一个用 Skill 审计评测集、扫参数选模型，一个演示从需求访谈到可验证 React 组件的完整产品流程。

README 第一行写明：这是工作坊材料，不维护，也不接受贡献。所以它更像一套可以照着做的课件和样例代码，而不是一个会持续更新的库。

适合谁

  • 准备在 Claude API 上做智能体的工程师：想看 Managed Agents 的会话、线程、Skills、自定义工具、记忆库、outcome 评分在真实小项目里怎么拼起来。
  • 要选模型、控成本的团队：rightmodel 和 eval-driven 两个工作坊讲怎么先确认评测本身可靠，再按“质量/美元”“质量/秒”比较配置。
  • 办活动、做内训的人：几个工作坊专门为“一屋子人共用一个 API key”、会场 Wi-Fi 这类情况设计，agent-battle 还附了主持人手册。
  • Claude Code 用户：how-we-claude-code 展示 Anthropic 内部的“访谈出规格 → 多方向设计稿 → 可在运行时验证的组件”流程。

门槛：几乎都需要 Anthropic API key，并且会产生真实的 API 费用；Managed Agents 相关的工作坊需要账号开通对应 beta，记忆“Dreaming”还要加入研究预览。

九个工作坊逐个看

目录主题你会做什么
rightmodel/挑对模型用 Claude Code 的 eval-audit-and-sweep Skill 分两步：先按清单审计评测集（任务设计、测试框架、指标、评分器，含 LLM 评委的偏差），再把评测放进“模型 × 扩展思考 × effort”网格里扫一遍，出三张对比图和一句话推荐。没有自带评测的，可用 tau2-bench 兜底。
agent-decomposition/用 Skills 和 MCP 组装多智能体（CwC 2026 · W5 · 45 分钟）接手一个户外用品零售商的库存智能体 StockPilot：12 个工具、3 个写死的子智能体、402 行系统提示词。把它拆成 Skills + 代码执行 + 一个放对位置的子智能体，跑在 Managed Agents 上；每改一步跑一次 12 题评测，看哪些题从失败变成通过（基线约 71%）。
how-we-claude-code/我们怎么用 Claude Code三个阶段：① 访谈式头脑风暴，产出一个免注册、按链接分账的 App 规格；② 四个不同视觉方向，各做成静态 HTML 稿并排比较；③ 一个 Vite + React 待办应用，每个组件声明夹具、不变量和机器可读的 DOM 契约，智能体或 CI 可以在运行时检查。前两段只给提示词（PROMPT.MD），第三段是成品。
ship-your-first-managed-agent/上线第一个托管智能体一个虚构电商的值班看板（Streamlit），凌晨两点三个告警同时响。分四步让 Claude Code 写代码、你做判断：① 一个带 runbook Skill 和自定义工具的智能体；② 多智能体：事故指挥官给每个告警开一个调查员线程；③ 记忆库：团队历史 + 智能体自己的笔记本；④ 文件输出：可下载的事后复盘 PDF。设计成全场共用一个 API key。
agent-battle/智能体对战（Claude 玩 Minecraft）45 分钟比赛：配置一个 Managed Agent（模型、系统提示词、Skills、MCP 服务器），让它通过 MCP 操控你本机的 Minecraft 机器人。挖到钻石最多者胜，token 少者优先；--eval 决策探针约 30 秒就能试一次配置，再决定要不要跑 5 分钟正式局。机器人主动外连活动服务器，本机不对外暴露端口。
agents-that-remember/会记事的智能体（CwC 2026 · W3 · 45 分钟）从一个“跨会话就失忆”的智能体出发，一次加一种记忆：先用记忆库做跨会话持久化，再用 Dreaming 服务把过去的对话记录整理成记忆，用原文的说法是“45 分钟从金鱼变同事”。
eval-driven-agent-development/评测驱动的智能体开发一个生成 PPTX 的 Managed Agent，迭代六个版本（朴素 → 视觉 → 字体 → 配色 → 信息密度 → 自检循环），每版用 10 题评测打分。评分器两层：程序化检查 .pptx 的 XML 指标，再让 LLM 评委看渲染出的幻灯片。目标是每次改提示词都有分数可看，不凭感觉。
production-ready-agent/Deal Desk：并购研究台聊天式界面背后是一支多智能体并购研究团队：协调者并行派活给四个研究子智能体，从记忆库读过往交易教训，经 MCP + Vault 访问 Linear，最后产出带评分的投资论点；界面实时显示每个事件，需要确认的工具调用要人点头。starter/ 留了待填的 API 路由，solution/ 是完整版。公司与财务数据都是虚构的。
research-desk/SEC 研究台用自托管的 Next.js 控制台搭一个读 SEC 文件的股票研究台：先跟一个空白智能体打招呼，再把它升级为“研究主管”，通过你自己服务器实现的自定义工具，为每只股票派一个分析师会话；分析师再分给子智能体专家，用 edgartools Skill 读财报，按 outcome 评分表打分，写入共享记忆库；最后用定时部署生成每周备忘录。仓库带 /workshop Skill 当助教。

怎么用

  1. 克隆并进入一个工作坊目录：git clone https://github.com/anthropics/cwc-workshops，然后 cd 到你要做的那个目录。各目录相互独立，依赖不同。
  2. 按该目录 README 装环境：Python 的多用 uv sync 或 pip install -r requirements.txt；TypeScript 的用 bun 或 npm；Managed Agents 相关的要装 Anthropic 的 ant CLI；eval-driven 还要 Docker（在容器里用 LibreOffice 渲染幻灯片）；agent-battle 要 Java 和 Minecraft（需自行同意 Minecraft EULA）。
  3. 配置 API key：复制 .env.example 为 .env 填入 ANTHROPIC_API_KEY，或按 README 导出环境变量。
  4. 在目录里打开 Claude Code：多数工作坊带 CLAUDE.md、Skill 或斜杠命令（如 /cwc-setup、/workshop act 1），可以让 Claude Code 带你一步步做，也可以对照 solution/ 自己写。
  5. 做完清理：这些工作坊会在你的 Anthropic 账号里创建智能体、环境、记忆库、文件和部署；有的带 cleanup.py，没有的要自己去控制台删，免得继续占资源或计费。

贯穿的几条主线

  • 先有评测，再改智能体：agent-decomposition、eval-driven、rightmodel 都把“每改一步就跑评测、看分数变化”当成基本动作，rightmodel 还要求先审计评测本身。
  • 拆而不是堆：把超长系统提示词和一堆工具，拆成按需加载的 Skills、代码执行和少数子智能体。StockPilot 那份 402 行的提示词就是反面例子。
  • 记忆分层：会话内上下文、跨会话的记忆库、再到从旧对话里整理出的记忆（Dreaming），ship-your-first 和 research-desk 也都用到了共享记忆库。
  • 人留在关键处：Deal Desk 的受控工具调用要人确认；ship-your-first 让 Claude Code 写代码、学员做判断。
  • 为现场设计：共用 API key、机器人主动外连、可重复执行的初始化脚本，这些都是为会场环境准备的。

核对与 ⚠️ 注记

  • 不维护：README 明说不维护、不接受贡献。Managed Agents 还在 beta，API、CLI 命令和字段可能已经变了，照做前先对照官方文档 ⚠️。
  • 需要开通 beta 或预览：agents-that-remember 要求组织先加入研究预览才能用 Dreaming；production-ready-agent 要求 API key 开通 Managed Agents beta。本站没有账号权限，没有实际跑任何一个工作坊 ⚠️ 未实测。
  • 费用：运行会调用真实 API。agent-decomposition 的基线评测就要约 9 分钟，ship-your-first 每次检查要 1–3 分钟，具体花费 README 没写 ⚠️。
  • 活动时间地点：仓库只写了“Code with Claude 2026”和部分工作坊编号（W3、W5）。提交记录里有 London、Tokyo 场次的准备，但每个工作坊在哪场、哪天开过，仓库没有说明 ⚠️ 未核实。
  • agent-battle 单人能不能玩：比赛依赖主持人部署的活动服务器（.env.event 里的地址）。会后这个地址是否还在线本站没有核；单人练习大概要按 HOST.md 自己部署一套 ⚠️ 推断。另：该工作坊声明不是 Minecraft 官方活动，与 Microsoft / Mojang 无关联。
  • 模型名：代码里出现的模型 ID 有 claude-sonnet-4-6、claude-haiku-4-5、claude-opus-4-7、claude-opus-5-5 等多代混用，用的时候请换成你账号里当前可用的模型 ⚠️。
  • 星数、提交数等是 2026-11-03 的快照，会变。

工作坊

  • rightmodel/ ——挑对模型：用 Claude Code 的一个 SKILL 审计 LLM 评测集，并在不同模型和推理参数（扩展思考、effort）上扫一遍，找出“质量/美元”和“质量/秒”最优的配置。
  • agent-decomposition/ ——用 Skills 和 MCP 组装多智能体系统：把一个靠 400 行提示词撑着的库存智能体，在 Claude Managed Agents 上拆成 skills + 代码执行 + callable_agents，并用评测验证每一步。
  • how-we-claude-code/ ——我们怎么用 Claude Code：分三个阶段走一遍 AI 辅助的产品流程——从访谈到规格，四个发散的设计方向（静态 HTML），再到一个 Vite + React 应用，其组件会输出机器可读的 DOM 契约，供智能体（或 CI）在运行时验证。
  • ship-your-first-managed-agent/ ——上线你的第一个托管智能体：一个 Streamlit 值班看板，三个告警同时打开，SRE 智能体面板处于离线状态。由 Claude Code 一部分一部分地填写 agent.py，你来做判断：先是一个带 runbook Skill 和自定义工具的智能体，然后是多智能体（一名事故指挥官，每个告警配一个调查员线程）、记忆库（团队历史加智能体自己的笔记本），以及文件输出（一份可下载的事后复盘 PDF）。设计成全场共用一个 API key 也能跑。
  • agent-battle/ ——智能体对战：45 分钟的比赛，配置一个 Claude Managed Agent（系统提示词、skills、MCP 服务器、模型），让它通过 MCP 驱动本地游戏机器人。钻石最多者获胜，token 最少者在平局时胜出；一个快速的 --eval 决策探针循环让你约 30 秒就能测试一次配置修改，再决定是否投入一局 5 分钟的正式运行。
  • agents-that-remember/ ——会记事的智能体：从一个跨会话明显失忆的托管智能体开始，一次叠加一种记忆原语——先用记忆库实现跨会话持久化，再用 Dreaming 服务整合过去的对话记录——45 分钟“从金鱼变成同事”。
  • eval-driven-agent-development/ ——评测驱动的智能体开发：把一个生成 PPTX 的托管智能体迭代六个版本（朴素 → 视觉 → 字体 → 配色 → 密度 → 自检循环），每个版本都用 10 个任务的评测集打分，评分器分两层（程序化的 .pptx XML 指标 + 对渲染后幻灯片的 LLM 评委），让每一次提示词修改都有度量，而不是凭感觉。
  • production-ready-agent/ ——Deal Desk：在 Claude Managed Agents 上的一支多智能体并购研究团队，前面是聊天优先的界面——协调者把任务委派给四个并行的研究子智能体，从记忆库读取过往交易的经验，经 MCP 访问 Linear，并产出一份带评分的投资论点；界面实时显示每个事件和每次受控的工具调用。
  • research-desk/ ——研究台：在 Claude Managed Agents 上搭一个 SEC 文件研究台，前面是自托管的 Next.js 控制台——先和一个你自己接好的空白智能体打招呼，再把同一个智能体升级（版本化更新）为研究主管，由它通过一个由你的服务器实现的自定义工具，为每只股票派出一个分析师会话；还包括子智能体专家、一个 edgartools Skill、按 outcome 评分的计分卡、共享记忆库，以及一个每周备忘录的部署。

# cwc-workshops

Workshop materials. Not maintained and not accepting contributions.

Materials from Anthropic-run **Code with Claude** workshops.

## Workshops

- [`rightmodel/`](./rightmodel) — *Picking the Right Model*: use a Claude Code SKILL to audit an LLM eval suite and sweep it across models and inference parameters (extended thinking, effort) to find the best quality-per-dollar and quality-per-second configuration.
- [`agent-decomposition/`](./agent-decomposition) — *Compose Multi-Agent Systems with Skills and MCP*: decompose a 400-line-prompt inventory agent into skills + code execution + callable_agents on Claude Managed Agents, with evals to verify each step.
- [`how-we-claude-code/`](./how-we-claude-code) — *How We Claude Code*: a three-phase walkthrough of an AI-assisted product workflow — interview to spec, four divergent design explorations as static HTML, and a Vite + React app whose components emit a machine-readable DOM contract so an agent (or CI) can verify them at runtime.
- [`ship-your-first-managed-agent/`](./ship-your-first-managed-agent) — *Ship Your First Managed Agent*: a Streamlit on-call dashboard with three pages open and an offline SRE Agent panel. Claude Code fills in `agent.py` one part at a time while you make the judgment calls: one agent with a runbook Skill and custom tools, then multiagent (an incident commander with an investigator thread per page), memory stores (team history plus the agent's own notebook), and file output (a postmortem PDF you download). Built to run with a whole room on one API key.
- [`agent-battle/`](./agent-battle) — *Agent Battle*: a 45-minute competition to configure a Claude Managed Agent — system prompt, skills, MCP servers, model — that drives a local game bot over MCP. Most diamonds wins, fewest tokens breaks ties; a fast `--eval` decision-probe loop lets you test config changes in ~30s before committing to a 5-minute run.
- [`agents-that-remember/`](./agents-that-remember) — *Agents That Remember*: start with a Managed Agent that's visibly amnesiac across sessions, then layer in memory primitives one at a time — a memory store for cross-session persistence, then the Dreaming Service to consolidate past transcripts — going "goldfish to colleague" in 45 minutes.
- [`eval-driven-agent-development/`](./eval-driven-agent-development) — *Eval-Driven Agent Development*: iterate a PPTX-generating Managed Agent through six variants (naive → visual → typography → palette → density → QA-loop), scoring each against a 10-task suite with a two-layer grader (programmatic `.pptx` XML metrics + LLM-as-judge on rendered slides) so every prompt change is measured, not vibed.
- [`production-ready-agent/`](./production-ready-agent) — *Deal Desk*: a chat-first UI over a multi-agent M&A research team on Claude Managed Agents — a coordinator delegates to four parallel research sub-agents, reads prior-deal lessons from a memory store, reaches Linear via MCP, and emits a graded investment thesis while the UI streams every event and gated tool call.
- [`research-desk/`](./research-desk) — *The Research Desk*: build an SEC-filings research desk on Claude Managed Agents behind a self-hosted Next.js console — say hello to a bare agent you wire up yourself, then promote that same agent (versioned update) into a head of research that dispatches one analyst session per ticker through a custom tool your server fulfils, with sub-agent specialists, an edgartools Skill, outcome-graded scorecards, a shared memory store, and a weekly memo deployment.
