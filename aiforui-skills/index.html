给智能体用的界面技艺：Emil Kowalski 的开源 AI Skills

把界面品味写成可安装的开源技能

来源 · Emil Kowalski · aiforui.dev/skills收录 · 2026-11-10查看原文 ↗

作者：Emil Kowalski · 目录页：aiforui.dev/skills · 仓库：emilkowalski/skills（MIT License，Copyright (c) 2026 Emil Kowalski） · 核对：2026-11-10（新加坡时间） · 移除请求

智能体写界面时，常常会选错缓动、加太多淡入，或把实线描边当成默认装饰。Emil Kowalski 把这些「看起来只差一点、叠加起来却很廉价」的判断，写成一套可以安装的技能，让代理按任务去调用。本页以这套开源技能为中心，并说明它和同站付费课程之间的界限。

一、目录页在卖什么，仓库里又有什么

aiforui.dev/skills 自称「AI Skills for Building Better Interfaces」，页面说明这些技能是免费、开源的，给设计师和工程师用来指挥智能体做更好的界面。目录写着「Available skills 17」，按「实际项目里你会伸手去用的顺序」分成五组：动手之前、搭建界面、打磨与评审、看整座应用、以及其他。站点标注最后更新于 2026 年 11 月 8 日。

同一套技能的源码在 GitHub 仓库 emilkowalski/skills。README 列出 18 项，比网站目录多出一项 write-swift（写现代 Swift，含值类型、Swift 6 并发、泛型、性能与 Swift Testing）。网站目录未收录这一项，本页在目录后单独注明。

安装命令在目录页和各技能页上都写得很明确：

npx skills@latest add emilkowalski/skills

单项安装可加 --skill，例如 npx skills@latest add emilkowalski/skills --skill emil-design-eng。作者还在 README 里放了技能更新的通讯订阅入口（aiforui.dev/skills/updates）；本站只记录该链接存在，未登记邮箱。

二、和付费课程的边界

这些公开技能被放在 aiforui.dev 上，和一门名叫「AI for Designers and Engineers」的付费课程住在同一座站点。课程页写：由 Emil Kowalski 讲授，面向希望「要 AI 的速度、但不降低标准」的设计师与工程师；候补登记可先看两节免费课，招生页面写明入学将于 2026 年 12 月 8 日重新开放。各公开技能页页脚也重复了这句招生日程。

两者不要混为一谈。网站目录上的 17 项（加上仓库里的 write-swift）是 MIT 许可的公开技能。课程页另称学员会得到「我每天都在用的 28 项 UI skills」、动画审查工具 Lapse，以及专属 Discord。变更日志里出现的 /emil-prep-for-prod、/emil-unslop-design、/emil-borrow-a-brain 等，并不在此次核对过的公开仓库 README 列表中。⚠️ 课程是否仍为 28 项、Lapse 的授权范围、以及哪些技能只对学员开放，均以作者站点当时页面为准，本站未登录课程、未逐项核对付费包。

团队授权页展示：购买 5 个席位，原价 1,495 美元，显示 10% 折扣后为 1,345.50 美元（2026-11-10 页面所示）⚠️，价格可能随时变动。个人课程标价在本次抓取中未稳定显示（页面处于等候名单状态），故不转写一个未核对的数字。课程页自报已有 4,500+ 名设计师与工程师参加 ⚠️，本站未核实。

三、技能目录

下面按目录页的五组来写，说明用我的转述，不逐页复制技能文档。括号里是调用名与目录页链接。

01 动手之前

先弄清该怎么说、用什么做、以及要不要先并排比较几个方案。

  • Animation Vocabulary（/animation-vocabulary）：把「顺一点、高级一点」换成准确的动效用语，让智能体知道你要的是哪一种变化。
  • Pick a UI Library（/pick-ui-library）：按作者信任的清单帮你选型，避免智能体手写一个 toast，或装上已经无人维护的包。
  • Prototyping（/prototype）：就同一块界面做出多个不同版本，并用切换器比较，而不是只生成一个再慢慢改。

02 搭建界面

目录页称这一组是「帮你为界面做出正确决定」的技能。

  • Design Engineering（/emil-design-eng）：作者说的「主技能」。不知道该调用哪一项时用它。它会判断某件事是否值得动画、挑选缓动与弹簧、处理按压态和感知来源的弹出层，并以「之前 / 之后 / 原因」表说明改动。比专项技能更宽、也没那么深。
  • Animate（/animate）：从零做一段动画，并选择曲线、时长和该动的属性。
  • Choreograph（/choreograph）：协调多个一起动的元素——谁先、谁后、谁并行，以及什么不该动。目录举例：删除一张卡片后，其余卡片如何就位。
  • Apple Design（/apple-design）：把 Apple 在 WWDC 设计讲座里谈的界面原则与流体运动，转写到网页语境。抽屉该用怎样的弹簧、松手后是否显得「死掉」，是这一项常被指向的问题。
  • Gestures（/gestures）：拖拽、轻扫与 sheet。技能页说明它用运动值 1:1 跟踪指针、越过边缘时橡胶回弹，并按距离或速度决定是否关闭，释放时带上动量。更新标注为 2026 年 11 月 8 日。
  • Mobile Native（/mobile-native）：让网页在手机上不像「缩小的网站」——粘滞的悬停态、点击高亮闪一下还不褪、100vh 问题、输入框导致页面放大、安全区与迟钝的点击，都在这一项里。

03 打磨与评审

  • Animation Performance（/animation-performance）：处理掉帧。目录页的目标写法是让动画跑在 60 帧；README 强调其中包含许多智能体容易漏掉的细问题，例如长列表里拖拽变卡、或随手加上 will-change。
  • Break UI（/break-ui）：用最糟数据去压界面——超长姓名、奇怪邮箱、单字母名字、巨大计数、空列表、非拉丁字符和表情。技能页说它会做一份报告并给出修复（例如 min-width: 0 或 Intl.PluralRules），并加上「演示数据 / 最糟情况」开关。更新标注为 2026 年 10 月 2 日。
  • Review Animations（/review-animations）：按作者的规则做一次严格审查，结果是通过或阻断。

04 看整座应用

目录页的提示是：不当下在写某一块时，先把整座应用拉开看一眼。

  • Find Opportunities（/find-animation-opportunities）：找出真正值得加运动的地方，也明确指出不该动的地方。
  • Improve Animations（/improve-animations）：普查代码里的动画，并给出可交给子智能体执行的、带优先级的独立计划。
  • Remove Animations（/remove-animations）：反过来做减法。README 举的例子包括：键盘快捷键上的运动、每个栏目都做一次淡入、一组 tooltip 各自再加一段延迟。

05 其他

  • Animate Expo（/animate-expo）：同一套标准，面向 React Native 与 Expo——手势、sheet、触感、屏幕转场，并尽量让运动离开 JS 线程。目录页写「与 Expo 团队合作完成」⚠️，合作形式与范围未在本次核对中另寻旁证。
  • Ask Sonner（/ask-sonner）：作者的 React toast 库 Sonner 的安装、样式、配方，以及开发环境重复弹出、Tailwind 类不生效等常见问题。

仓库有、目录页没有

write-swift（/write-swift）：只出现在 2026-11-10 核对的 README 参考列表中，不在网站 17 项目录里。说明是写现代 Swift：值类型、Swift 6 并发、泛型、性能与 Swift Testing。若你只从网站安装说明进入，可能会漏掉这一项。

四、作者怎么解释这套技能

README 的核心判断很短：智能体往往没有好品味。入场动画用了该用 ease-out 却写成 ease-in，或者把实线边框当成半透明阴影的替代，这些小错会叠成「能用，但不怎么好」的界面。技能的作用，是把代理可能犯的小错列出来，并说明怎么改。作者把它称作通向好界面的捷径，也是从「一片 slop」里走出来的捷径。

他同时写得很清楚：这些技能是领域经验的副产品。「AI 并不能替代这种经验，它放大你能从中得到的东西。」所以仍要学习写代码、做设计，或在任何领域里把专业养厚。经验来源，README 写的是他在 Vercel 与 Linear 的工作；课程首页进一步自称现为 Linear 的 design engineer，此前在 Vercel 设计团队，并称 Sonner 与 Vaul 每周从 npm 下载超过 8,000 万次、前作 animations.dev 已有 13,000+ 名学员 ⚠️。职务、下载量与前作学员数为站点自我介绍，本站未独立核实。

同站还有 /lab 互动实验室，以及课程变更日志（称课程于 2026 年 8 月开放，后续更新对已购学员免费）。这些页面服务课程与展示，不属于本次开源技能目录的正文。

写给设计师和工程师的 Skills

给设计师和工程师，帮他们做出更好的用户界面。

动画对不对、设计对不对，往往很难当时就知道。这些技能想让你更快走到那些正确的决定。

它们依据我在 Vercel、Linear 这类公司工作多年的经验。

这里的全部技能，都是领域专长的副产品。AI 并不能替代这种专长，它放大你能从中得到的东西，也让你相对其他人变得更好。

所以，去学写代码、做设计，或在任何其他领域里把专长养起来。这件事极其值钱。

想跟上我这些技能的更新，可以在这里订阅：

订阅通讯

安装

npx skills@latest add emilkowalski/skills

为什么要用？

智能体并没有很好的品味。

我见过很多次，它们给动画选错了材料。入场动画本该用 ease-out，却用了 ease-in（这里解释过为什么）。或者在界面上用实线边框，而不是半透明的阴影。

这些小事会叠加起来，让你的界面要么出色，要么……也就一般。

正如 Agents with Taste 一文所解释的，这些技能列出了智能体可能犯下的各种小错，并说明该怎么修正。

这是通向出色界面的捷径。也是在一片平庸生成物里显出来的捷径。

参考

  • emil-design-eng — 主技能，以动画为主，也包含一些设计建议。
  • animate — 从零做一段动画，并选择正确的曲线、时长、属性等等。
  • animate-expo — 同一标准，面向 React Native 与 Expo：手势、sheet、触感、屏幕转场，并让运动离开 JS 线程。
  • review-animations — 按我的规则，严格审查你的动画。
  • improve-animations — 审查代码库中的全部动画，并给出带优先级、可独立执行、能交给任意智能体的计划。
  • find-animation-opportunities — 在界面里寻找真正能从运动中受益的位置，同时也告诉你什么不该动画。
  • remove-animations — 寻找机会的反面：去掉应用并不需要的动画。可以想想键盘快捷键上的运动、每个栏目的淡入，以及一组 tooltip 里每一条再加的延迟。
  • choreograph — 协调多个一起做动画的元素：谁领、谁跟、谁并行，以及什么根本不该动。
  • animation-performance — 修复掉帧的动画。其中包含许多大多数智能体会漏掉的细问题。
  • animation-vocabulary — 用准确的词告诉 AI 你到底要什么，从而得到更好的动画。
  • apple-design — Apple 的界面设计与流体运动原则，提炼自他们的 WWDC 设计讲座，并转写到网页。
  • gestures — 做拖拽、轻扫和 sheet：1:1 跟踪手指，带上释放时的速度，并允许在动画中途被接住。
  • write-swift — 写现代 Swift。包括：值类型、Swift 6 并发、泛型、性能，以及 Swift Testing。
  • pick-ui-library — 让智能体按我使用并信任的库来选型，而不是手写一个 toast 组件，或装上一个已废弃的包。
  • prototype — 就你描述的那一块 UI，做出多个不同版本，并用切换器浏览。
  • mobile-native — 让网页应用在手机上接近原生：粘滞悬停、点击高亮闪烁、100vh 问题、输入框放大页面、迟钝的点击、安全区，以及其余把「网站」和「应用」分开的小修正。
  • break-ui — 用最糟数据去压你刚做的界面：长名字、奇怪邮箱、单字母名字、巨大计数、空列表、过长标签。
  • ask-sonner — 使用我的 toast 库 Sonner 的指南。包含安装、样式、配方，以及对最常见问题的修复。
