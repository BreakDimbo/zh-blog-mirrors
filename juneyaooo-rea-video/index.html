rea-video：逐镜头逆向拆解一条视频是怎么做的

Reverse-engineer any video, shot by shot

来源 · JuneYaooo/rea-video（GitHub）收录 · 2026-11-04查看原文 ↗

项目：JuneYaooo/rea-video（GitHub）· 作者 JuneYaooo · 本站导读，非翻译

rea-video 不生成视频，而是回答“这条视频是怎么做出来的”：把一条参考视频切成镜头，逐镜判断底层画面是实拍、AI 生成、3D、代码模板还是录屏，再拆出字幕花字、剪辑节奏和声音来源，最后按实拍 / AI / 代码三条路线写复刻方案。它以 agent skill 的形式交给 Claude Code、Codex 一类能跑命令的智能体来用。

版权说明：仓库根目录没有 LICENSE 文件，GitHub 也未识别出许可证（2026-11-04 核）；仅 pyproject.toml 写有 license = { text = "MIT" }。在作者补上正式许可证文件之前，本站按“未明确授权”处理：只做导读，引用原文仅限短句，不转载 README 全文、案例截图与视频。案例素材里有真人出镜画面，也一律不转载。

一句话定位

仓库简介写的是“逆向一切视频：实拍口播、桌拍、AI 视频、3D、代码动效、混剪，逐镜拆出画面、花字、剪辑和声音是怎么做的，并给出复刻方案”。思路来自 REA（Reverse Engineer Anything）：从现象追到实现，结论附证据。

它拆什么

  • 底层画面 10 类：实拍、AI 视频、数字人、3D 渲染、2D 动画、定格动画、代码模板渲染、录屏截图、静态图推拉、静帧。其中 2D 动画和定格动画工具测不出，要靠看图判断。实拍镜头还会看是否经过 AI 加工（换脸、对口型、风格化、换装、换背景）。
  • 剪辑包装层：逐句字幕时间轴（可导出 SRT / ASS）、花字颜色描边与入场方式、贴纸 / 表情包 / 画中画的位置和时长，以及切点与节拍。
  • 真实素材：区分“画面里嵌入的真实像素”（复刻时必须拿到原文件）和“AI / 3D 画面里出现的商品、人物”（复刻时要准备的参考图）。
  • 声音：人声是真人还是 TTS，配乐是 AI 生成还是曲库、BPM 与调性，音效卡在哪个画面事件上。
  • 实拍拍法：景别、机位、布光（README 称 12 种方案附器材）、调色风格。

怎么判断

  1. 切镜头、分音轨：按镜头切开，用 UVR MDX-Net（onnxruntime，首次运行下载约 67 MB 模型）把声音拆成人声、配乐、音效。
  2. 取证据：测画面（帧率规律、噪点、是否整张图在推拉、文件里有没有 AIGC 标识）、看图（手指、文字、物理细节）、听声音（BPM、调性、唱还是说）。
  3. 综合判断：AIGC 标识、帧率这类硬证据优先于“看起来像”；几方冲突时标出来交给 agent 看图复核。SKILL.md 的核心原则是“确定不了就如实写‘待确认’”，宁可给出“倾向 AI 70%”也不编确定答案。
  4. 出复刻方案：按目标视频模型的实际能力分批——单次能生成多长、能否一次出多镜、能吃几张参考图。各家模型能力表放在 rea_video/capabilities/。

用法

在 agent 里说一句“安装 rea-video，然后拆解这条视频”即可；agent 会跑 scripts/install_skill.sh 装好 CLI 并读 SKILL.md。标准流程是 rea-video decompose 产出 breakdown.json、report.html、分镜联系表和音频图，再 rea-video summary 看低置信镜头；能看图的 agent 还要走 review → apply-review，把自己的看图判断与确定性结果融合（不是直接覆盖）。依赖 ffmpeg 与 Python ≥ 3.10；可选配一个看视频的模型（README 举 Gemini、豆包），不配也能离线跑。

准确率（作者自测）

README 与 eval/RESULTS.md 给出按镜头时长加权的“制作方式”准确率：只用工具时调参集 15 条 98.3%、留出集 99.6% / 98.9%、公众号转码视频 10 条 88.6%；加看图模型与 agent 复核后转码视频达 99.6%–100%。⚠️ 这些均为作者在自建小样本上的自测，未经第三方复现；RESULTS.md 自己也写明 holdout 集“已不完全独立”，用户真实素材的 holdout2“首轮只有 75.6%”，修复后才到 97.2%。抖音带货两条只用工具仅 46%，要靠看图纠正到 97.5%——平台压缩视频是明显短板。

和复刻工具的关系

rea-video 自己不出片。README 的 FAQ 把它和 Hypit 对比：Hypit 拿参考视频直接重做，不区分原片怎么拍；rea-video 先判断每镜是拍的、生成的还是代码做的，再分别给拍摄方案、提示词或代码思路。要“换元素复刻”，作者配套的是同账号的 cheap-claude-video，README 展示的对比片用自部署 MiniMax H3 + gpt-image-2 关键帧生成。⚠️ 复刻效果仅见作者演示，本站未实跑。

值得注意的地方

  • 把“证据优先级”写进流程：元数据与帧率等可测量信号压过 VLM 的主观判断，这对 AI 检测类工具很重要——README 案例里看图模型把 AI MV 镜头说成“影视剧实拍”，是 agent 从奏折上的伪汉字认出的。
  • 作者在 FAQ 里明确：工具用来学习结构、节奏和做法，“请勿直接搬运他人的画面、音乐、角色或肖像”，投放时遵守平台 AI 内容标识要求。
  • 项目很新：2026-10-30（UTC+8）建库，截至 11-04 约 385 星、66 fork，版本 0.1.0。
