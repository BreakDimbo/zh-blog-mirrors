vork：让智能体用代码导演三维与 VFX 的无头渲染内核

An agent-native rendering kernel · 项目导读与许可边界

项目：Voyager / voyager-so/vork；版权：Nullframe, Inc. · 原文与仓库 · vork Preview License · 核对：2026-11-07（SGT） · 移除请求

vork 的想法不是给 AI 再造一个能点按钮的三维编辑器，而是把场景、材质、灯光和模拟交给代码：智能体写场景，渲染一张图，检查结果，再修改。它是 Voyager 的无头三维与 VFX 内核，采用 Rust 和 Slang，通过 Vulkan 或 Metal 使用 GPU。

先看许可：这是研究预览阶段的源码可见软件，不是开源项目。当前版本可免费用于商业工作，但不能随意再分发修改版或架设供他人提交任务的托管渲染服务。本页仅作独立中文导读、使用少量短引，不镜像 README、不转载示例图和视频。

一、它解决什么问题

传统创作软件通常先设计供人操作的界面，再给智能体增加自动化入口。vork 反过来，让智能体直接生成 JSON 场景，或通过 Python / TypeScript SDK 描述镜头；在需要特殊效果时，再写 GPU 程序。常规镜头不必编写底层着色器，特殊镜头则可进入更深的光线与材质控制层。

这条路线的价值是把“写代码—出图—看图—修正”缩短成一个循环，而不是宣称模型能一次生成最终画面。它也不是视频生成模型：模型负责描述与修改，图像由渲染程序计算。

二、公开示例说明了什么

  • 百万鸟群：GPU 计算程序控制群体行为，镜头穿过鸟群；README 特别说明，模拟的百万只鸟并不拍翅，近景鸟与镜头另行编排。不能把数量直接等同于百万只完整骨骼动画。
  • 实拍 VFX：把三维物件放入跟踪过的实拍镜头，以代理几何、遮挡与补光完成合成。跟踪求解与单视图浮雕都是估计，不是自动恢复完整真实场景。
  • 黑洞：通过公开的光传播接口编写弯曲光路；作者明确说这是数值近似，不是精确相对论求解器。
  • 资产导入：展示 glTF 资产、扫描模型及 Blender 场景转换。示例资产有 CC0、CC BY、CC BY-SA、Pexels 等不同条款，不随引擎统一许可。
  • 水体：GPU 流体实验有有限网格与粒子预算，细小结构和双向刚体耦合等仍有限制，不应当作成熟模拟软件的通用替代品。

本页不转载实拍人物画面，也没有下载或观看演示视频。以上为对文档的核对，不是本站运行验证。

三、怎样理解工作流

作者建议从 vork help 开始，先做一个小场景、出低成本预览、检查图像，再精修镜头与灯光。查询某个功能时按主题或字段取帮助，避免一次塞入所有接口说明。

档位适用阶段需要注意
std/previs快速构图与镜头预演灯光和阴影不同于交付档，速度不能当成最终画质的表现。
std/draft / std/final混合渲染草稿与默认交付默认低采样加降噪；部分间接光被近似，室内可能变暗。
std/path需要更完整光传输的场景可能更慢；仍有反弹、截断、采样和降噪限制，不是物理真值。

提高采样数不能补回算法本身省略的光传播。 如果问题是室内反射或复杂玻璃，不要只堆采样，要换传输路线并重新看图。场景内容与渲染质量分离，才方便在同一份场景上比较。

四、性能数字必须连同条件一起读

README 的关键限定是 not equal-quality speedups：这些计时不是等画质加速。默认 final 的七场景影片比较，自报相对 EEVEE 为 1.14–2.32 倍；但渲染配置、采样、降噪和计时边界并不一致，Blender 基线还沿用先前测量。路径追踪的两个静帧例子反而比 Cycles 慢。

鸟群影片的 Blender 数字主要由少量帧外推，不是完整影片实测；不能拿它当端到端同质量对比。初始化、着色器预热、传输与资产准备也可能不在影片计时里。README 给出的 skim 示例，初始化、预热与影片中位数合计约 8.45 分钟，仍不含资产准备和传输。

更重要的是，基准文档承认 Blender 5.2.1 的相机准备辅助脚本当前失败，历史比较暂时无法独立复现；现有 runner 的配置也不能原样重现部分历史表格。⚠️ 本站未跑基准，所有速度数据均为作者报告，不构成实测结论。

五、先核对电脑，再承诺镜头

  • Linux / Windows：支持带所需硬件光追功能的近期 NVIDIA GPU。AMD、Intel 和 CPU / 软件渲染不受支持；A100、H100、H200、B200、B300 等并不会因为“新”就自动满足要求。
  • Mac：Apple Silicon + Metal；随包 Slang 工具链要求 macOS 26，旧系统未经确认，Intel Mac 不支持。主程序能打印版本，不代表 Slang 工具链一定能运行。
  • 冷启动：新 GPU 程序第一次可能编译数分钟，即使预先运行 setup，也不保证所有镜头即时出图。
  • 当前限制：没有体积雾、烟等参与介质；大型场景与密集透明物体可能失败，降分辨率不一定解决。细线、毛发、散景和稀疏高光在低采样下可能失真。

若准备试用，先从官方 Releases 的完整平台包与校验说明开始，保留二进制旁的运行库、SDK 和许可文本。Python 和 TypeScript SDK 从本地安装目录安装；npm 上名为 vork 的包与本项目无关。本文没有安装、执行安装脚本或提交渲染任务，也未单独确认当前 Release 下载资产可用性。

七、适合谁

如果你希望智能体用代码反复调整三维镜头、需要比 GUI 自动化更直接的渲染接口，并且具备受支持 GPU，vork 值得作为实验工具研究。如果你需要成熟的体积效果、稳定复杂透明场景、全平台兼容，或准备经营公共渲染服务，先不要把研究预览当成生产承诺。

最有价值的不是“替代 Blender”这个口号，而是把智能体能写的程序，与可检查的渲染结果连起来；真正的交付能力仍要逐镜验证。
