一句话看懂

gbro-collage-broll 是狗哥笔记（@gbroai / pyang5166）的纸拼贴 B-roll Skill：把一句约五秒的口播拆成一个可读的视觉隐喻，先定静帧，再从纯色空场逐件组装成动画。余温（@gkxspace）推荐的是作者刚展示的 Image 2.6 新路线，但当前公开 README 仍然是 Gemini Omni Flash 视频生成路线。两者不能混为一谈。

作者在原文末尾明确说，新版还在调试；余温也在评论补充“仓库好像还没更新”。本次实时读取 README，仍显示三闸门和 Gemini 依赖。⚠️ 不能把它当作已经发布、克隆即用的 Image 2.6 Skill。

真正值得借用的方法

  1. 先审隐喻，再花生成额度。 一句口播只做一个视觉命题；用三到六组大物件，避免一个画面塞进多个意思。
  2. 案例图负责对齐，参数负责复现。 纯色色场、黑白半调网点、彩色卡纸、奶油白细边、软阴影、纸纤维，各自写成具体约束，而不是只说“高级”。
  3. 静帧不是海报，而是动画的终点。 提前留出空场和物件进出空间；先冻结风格与构图，再生成运动。
  4. 动作写物理顺序。 写清从哪进、做什么、停在哪、何时退场；滑入、落下、翻面、剪开比“浮现”“呼吸感”更符合纸拼贴。
  5. 循环也要验收。 检查空场是否偷露纸片、组装过程是否真实、尾帧是否一致、首尾接头是否跳动；最后用 ffprobe 检查交付规格。

怎么开始，以及别误信什么

公开仓库可按 README 的安装与触发方式使用，但当前路线涉及按量计费的视频服务；先确认费用、隐喻与静帧，再生成。这里没有运行 Skill，也没有调用任何生成服务。

⚠️ “0 成本”不是免费承诺。 作者的解释是复用已付费订阅额度，不再逐条支付视频 API 费用；订阅、额度、失败重试与人工时间仍然存在。Image 2.6、Opus 5.5 的命名和生成能力来自作者自述，本次未独立验证官方可用性；“HTML 代码画不出复杂纸拼贴”也是作者的经验判断，不是代码渲染的能力上限。

昨天 Codex 更新了 image2.6，核心是能直接生成 GIF 了。 我当晚就拿它跑了四条拼贴 B-roll，全程没碰视频模型。

说实话，这次给我的震撼比 Opus 5.5 写代码做视频那一波还大。 原因就两个：成本，和能做出来的画面有多复杂。 Opus 5.5 写代码做视频，本质上是 HTML 动画。数字跳动、卡片翻转、信息图，它做得又快又准。但一到「一只手拿剪刀，把月亮从纸上剪下来」这种画面，代码就画不出来了：纸的毛边、半调网点、手的形状，这些得靠图像模型。 以前要做这种有手工质感的镜头，我得接视频模型的 API，按条付费。一条5秒的视频大概是1块钱。 结果就是，我舍不得为一句口播单独做一个镜头。 现在整条链路都在 Codex 里跑完，用的是本来就在付的订阅额度。不接 API，不配密钥，不再为每条单独付钱。 对天天剪口播的人来说，这意味着一句话也配得起一个专门的镜头了。 我把自己的 skill 改了 我有个自用的 skill 叫 gbro-collage-broll，专门把一句 5 秒左右的口播，做成半调纸拼贴风的 B-roll。 改之前的流程是这样的： 先出视觉隐喻，等我确认 再出静帧，再等我确认 拿纯色空场当首帧、静帧当尾帧，调 Gemini Omni Flash 生成首尾帧视频（更早用的是 Veo） 拿到视频去掉音轨 改完变成： 只确认一次隐喻 image2.6 出静帧，AI 自己按清单检查、有问题自己重出 以静帧为终点，image2.6 直接出循环 GIF GIF 转成 MP4，方便进剪辑软件 具体改了三处： 视频模型整个拿掉了。 依赖从「Python + google-genai SDK + API 密钥」变成「Codex + ffmpeg」，装机门槛低了一大截。 两道确认砍成一道。 我发现真正需要人判断的只有隐喻这一步。静帧有没有假字、主体集不集中、纸片是不是太碎，这些都能写成清单让 AI 自己查。我盯着看反而是浪费时间。 交付从 MP4 变成 GIF + MP4 两份。 GIF 发推、放笔记里直接动，MP4 拖进剪映用。

下面是我这几天跑下来的经验。如果你也想用 image2.6 低成本做 AI 视频，又想把质量做上去，可以按这四步走： 隐喻 → 定风格出静帧 → 描述动作出 GIF → 转 MP4

第一步：先确认隐喻 口播是抽象的。比如「经验每次都在重复消耗」，这句话你没法直接丢给模型出图，丢了也是随机抽卡。 所以第一步要把它翻译成一个画面。我的 skill 会给出这样一张卡：

为什么一定要在这里停下来确认？ 因为隐喻错了，后面每一步都白做。看一段文字只要十秒，重出一组图要几分钟，还要烧额度。 把人的判断放在最便宜的那一步，这是免抽卡的关键。 几条规则： 一句话只做一个隐喻，别想一个画面讲三件事 物件控制在 3–6 个，多了语义变弱，动起来还会互相遮挡 不要把文稿的字放进画面，画面负责隐喻，字幕负责文字 批量做的时候，让几条隐喻前后成叙事。比如先拍手工消耗、经验流失，再拍规范沉淀、人机分工 第二步：定风格，出静帧（最关键的一步） 这一步最决定成片质量，篇幅我多花一点。 1. 风格不能光靠形容词，一定要有案例 你跟模型说「高级的杂志拼贴风」，出十次能给你十种拼贴。 形容词每个人理解都不一样，模型也一样。要让风格稳定，必须给它一个具体的案例。也就是你觉得满足这个你心中这个风格的图究竟是什么样的。 有了案例之后，我的 skill 会做一件事：把案例拆成可执行的材料参数，写进一份 visual-spec.json。拼贴风拆出来是这样的： 平涂色场：背景是一整块强烈、均匀的纯色纸，没有渐变 黑白半调剪片：主体是黑白网点照片剪下来的纸片，看得见印刷网点 彩色卡纸点缀：关键物件（卡片、按钮、胶片）才用红、黄、青、橙、紫 机切边 + 奶油白描边：每块纸边缘干净利落，外圈一道细细的暖白边 柔和投影：低透明度的纸片阴影，让纸有一点厚度 纸纤维颗粒：未涂布纸的细纤维质感 案例负责让你和模型看到同一个东西，参数负责每次都能复现它。两样缺一不可。

  1. 颜色跟着语义走 我以前默认全用钴蓝底，一批看下来很单调。现在按意思挑底色： 焦橙 / 红：时间消耗、劳动、紧迫 芥末黄：工具、警示、经验漏失 墨绿：认知、审美、系统重置 深紫：规范、沉淀、长期记忆 青绿：判断、协作、自动执行

同一批作品，设计语言统一，底色各不相同。彩色纸片只用在需要强调的地方，不为了彩色而彩色。 3. 构图要给动画留位置 静帧不是一张海报就完事了，它是 GIF 的最后一帧。所以出图时就要想好它怎么动起来： 主体放在画面中间 70% 的区域 留出大块干净的纯色空白，动画要从这块空场开始拼 画面由 3–6 个能分开的大纸片组成，不要满屏碎片 碎片太多，动起来就是一锅粥。 4. 把模型的坏习惯提前禁掉 图像模型很爱在画面里塞假字、假 logo、假界面。拼贴风尤其容易冒出报纸上那种乱码小字。 所以提示词里要明确写：无文字、无字母、无数字、无 logo、无水印、无 UI、无字幕、不要光滑 3D、不要写实场景。 我的静帧提示词模板长这样，可以直接拿去改：

  1. 为什么一定要先出静帧 这是我最想强调的一点：跳过静帧、直接让 image2.6 出 GIF，质量明显差一截。 道理也简单。一步出 GIF，模型要同时决定风格、构图、动作三件事，等于三件事一起抽卡。结果往往是画面发糊、纸片闪烁、假字乱冒。 先把静帧定死，GIF 的任务就只剩一件事：把这张图从空场拼出来。终点已经确定，模型只管过程。
  2. 静帧出来先过一遍清单 隐喻是不是一眼能看懂 主体集不集中 有没有假字、logo、水印、UI 纯色空场留够了没有 是 3–6 个大组，还是满屏碎片 同一批是不是质感统一、底色有变化 有一条不过就重出。这个清单我已经交给 AI 自己跑了，不用人盯。 第三步：怎么描述动作，让 AI 出 GIF 静帧定好之后，动作描述的核心就一句话：从空场开始，把纸片一块块拼成这张静帧。 我管这个叫 assemble-from-empty。为什么不用「轻微漂移」「缓慢推镜」「呼吸感」这种描述？因为放在 GIF 里，这些小动作看起来就是画面在抖。拼贴风的魅力在定格动画那种一块纸「啪」地卡到位的感觉。 我的 skill 描述动作有四个规矩。 一、顺序固定。 基础结构先进场，然后是人物或关键卡片，再是连接件，最后是动作和结果。拼完定格一会儿，再清场回到空场，正好接上下一轮循环。 二、每个物件写清四件事。 从哪进、做什么动作、停在哪、什么时候走。 三、用物理动词。 滑入、落下、卡位、翻面、剪开、装订、点亮。别写「出现」「浮现」，那是淡入淡出，不是拼贴。 四、镜头锁死。 不切镜、不缩放、不变形、不加静帧里没有的新物件、不出文字。 拿我昨天做的「把月亮剪下来」举例，5 秒的动作是这样排的：

GIF 出来之后，别只看最后一帧。要逐段检查：入场有没有提前露出纸片、中段是不是真的一块块拼、定格是不是和静帧一致、循环接头会不会跳一下。 第四步：GIF 转 MP4 GIF 发推很方便，但剪映、PR 对 GIF 的支持一般，所以我最后都会转一份 MP4。 一行 ffmpeg 就够：

几个参数解释一下： -ignore_loop 1：GIF 带着无限循环标记，这里显式让 ffmpeg 只读一遍。要是设成 0，它会按标记一直循环读下去 fps=24：我的 GIF 按 20fps 出，这里统一成剪辑软件习惯的 24fps scale + pad：缩放到 720×1280 竖屏，比例不对就补边，不拉伸 -pix_fmt yuv420p：兼容性最好的像素格式，手机、剪映都能正常播 -an：不要音轨，B-roll 的声音在剪辑里统一处理 转完用 ffprobe 看一眼：5 秒左右、720×1280、24fps、H.264、没有音轨，就可以拖进时间线了。

顺带说一句，拼贴风天生适合走 GIF：大面积平涂色块加黑白网点，用到的颜色本来就少，GIF 的 256 色基本够用，不太会出现色带。 最后 整个流程总结一下： 隐喻先确认：把人的判断放在最便宜的那一步，免抽卡 风格靠案例，静帧必须先出：案例让风格稳定，静帧给 GIF 定终点 动作从空场拼起：顺序固定、物理动词、镜头锁死 GIF 转 MP4：一行 ffmpeg，直接进剪辑 这个 skill 我开源在 GitHub： https://github.com/pyang5166/gbro-collage-broll 现在仓库里还是旧版（Gemini Omni Flash 方案）。image2.6 的新版我再调试两天，稳定了就推上去。 想第一时间用的，可以先点个 star，更新了我会在这里说一声。

gbro-collage-broll

（演示 GIF 仅见上游仓库，本页不转载。）

把一句约 5 秒的口播文稿，压成一个 鲜明的视觉命题，再生成高级编辑风半调纸拼贴（halftone paper-collage）组装动画 B-roll。

将约五秒的口播文稿变成具有高级编辑质感的纸拼贴 B-roll，从空场开始组装，使用 Gemini Omni Flash 首尾帧视频生成。

效果

  • 强烈平坦的纯色纸面色场 + 黑白 halftone 照片剪贴 + 彩色卡纸点缀
  • 元素从空场逐件滑入、卡位、组装（stop-motion 质感），不是淡入或慢 zoom
  • 默认交付 9:16、5 秒、720×1280、24fps、无声 MP4，可直接垫在口播下面

工作流：三闸门审批

这个 skill 的核心不是 prompt 模板，而是强制的三阶段审批，让你把注意力花在审美判断上，而不是烧生成费用：

  1. Gate 1 · 隐喻确认 — 只输出视觉隐喻方案（核心意思 / 关键物件 / 底色 / 组装顺序），不生成任何图片视频
  2. Gate 2 · 静帧确认 — 确认后才生成彩色拼贴静帧 + contact sheet，再次等你确认
  3. Gate 3 · 视频生成 — 静帧通过后自动用 gemini-omni-flash-preview 做首尾帧组装动画，附完整 QA（逐秒抽帧、首帧空场验证、尾帧对照）

批量模式下支持部分通过：只有确认过的条目进入下一阶段。

环境要求

首次触发时 skill 会自动运行 scripts/check_setup.sh 自检，并针对缺失项给出配置指引。需要：

依赖 说明
Codex 环境 Gate 2 静帧生成依赖内置 image_gen 工具
GEMINI_API_KEY Google AI Studio 创建，视频生成按量计费
Python >= 3.10 用于视频生成脚本
google-genai >= 2.10.0 skill 会引导创建共享 venv ~/hyperframes-projects/.omni-venv/
ffmpeg / ffprobe 首尾帧处理、去音轨、contact sheet

视频生成脚本（scripts/generate_video.py + scripts/upload_file.py）已随 skill 自带，无需额外安装其他 skill。

安装

把整个目录放进你的 agent skills 目录（例如 ~/.agents/skills/ 或 ~/.claude/skills/）：

git clone https://github.com/pyang5166/gbro-collage-broll.git ~/.agents/skills/gbro-collage-broll

使用

对你的 agent 说：

collage b-roll：很多人以为 AI 是来替你思考的，其实它更像一面镜子，会把你问题里的漏洞照出来。

触发词：collage b-roll、纸拼贴 b-roll、半调拼贴、拼贴风格配画面、gbro-collage-broll。

然后按 Gate 1 → Gate 2 → Gate 3 逐步确认即可。批量给多句文稿也可以，每句一个隐喻一条成片。

FAQ

为什么强制两次人工确认？ 错误的隐喻或静帧直接进视频生成，浪费的是真金白银的 API 费用。Gate 1 改文字是免费的，Gate 2 重生一张图远比重跑一条视频便宜。

成片首帧边缘露出一点纸片？ 轻微的可以接受；严格空场需求建议用可编辑时间线的动画工具补前段。

能换视频模型吗？ 默认固定 gemini-omni-flash-preview，明确指定其他模型时才切换。
